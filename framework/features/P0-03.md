# P0-3. Verification (Self & Collective)

> **Chain:** [EP-3](../principles/EP-03.md) → Verify before declaring completion

## L2: Targeted Enhancement

Agents autonomously detect and correct errors before human review.

## L3: Design Decisions

Test suite wired into task completion flow; error logs piped back into agent context; pre-completion checklists; consensus voting for MAS.

## L4: Concrete Actions & Tools

- **Action:** Wire test suite execution into the agent's task completion flow.
- **Action:** Pipe error logs back into agent context for autonomous fix attempts.
- **Action:** Add pre-completion checklists that gate task finalization.
- **Tool:** Test runners (Jest, pytest, go test) integrated into agent workflows.
- **Tool:** Error log parsing and context injection utilities.

## L4: Prevention

- **`P0-3` Prevent Unverified Commits:** All code must pass 'npm run smoke' and 'npm run check' before it is committed or pushed. Enforce this with pre-commit hooks and CI gates.
- **`P0-3` Prevent Non-Deterministic Verification:** Verification signals must be machine-parseable (Exit 0/1) with JSON failure reports where applicable.
- **`P0-3` Prevent Cascading Hallucinations (Error Propagation):** Pre-commit hooks for unit/integration/E2E tests; required 'npm run audit' before merging; automated linting and structural checks; collective verification in MAS; Machine-Readability First.

## L5: Gap Signals

- Agent submits- Code committed without running tests
- Silent regression of structural harness files
- CI allows push of broken code
- Agent declares "task complete" without verification
- Human must manually verify every agent output
