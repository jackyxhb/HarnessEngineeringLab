# P2-3. AI Auditors & Collaboration Channels

> **Chain:** [EP-16](../principles/EP-16.md) → No author is their own best reviewer

## L2: Targeted Enhancement

Every substantial output is independently reviewed before merging.

## L3: Design Decisions

Automated code review (agent-as-reviewer); defined review criteria (correctness, style, security, architecture); generator/evaluator separation; escalation to human for ambiguous cases; review feedback loops.

## L4: Concrete Actions & Tools

- **Action:** Assign dedicated reviewer agents that audit code quality independently from the generating agent.
- **Action:** Define clear review criteria: correctness, style compliance, security, architecture alignment.
- **Action:** Enforce generator/evaluator separation — the agent that writes the code should not be the same agent that approves it.
- **Tool:** Agent-as-reviewer configurations.
- **Tool:** PR review automation tools.
- **Tool:** Collaboration channels (shared review logs, comment feeds).

## L4: Prevention

- **`P2-3` Prevent Evaluation Overfitting:** You must prevent the system from overfitting to static benchmarks. Prevent this by utilizing dynamic benchmarking and "Agent-as-a-Judge" frameworks to continuously create challenging, evolving evaluation instances.

## L5: Gap Signals

- Agent-generated code is never independently reviewed
- Same agent generates and approves its own output
- No automated review criteria — reviews are ad-hoc and inconsistent
- Review findings not tracked or acted upon

## L5: Improvement Policies

| Tier | Action | Dimensions |
| ------ | -------- | ------------ |
| 1 | Assign dedicated reviewer agent for all substantial outputs | Maturity |
| 1 | Define and enforce review criteria (correctness, style, security, arch) | Effectiveness |
| 2 | Enforce generator/evaluator separation | Risk |
| 2 | Implement dynamic benchmarking and evolving evaluation instances | Effectiveness |
| 3 | Build review metrics (defect escape rate, review turnaround time) | Human Role |

## L5: Measurement

- 100% of substantial outputs independently reviewed
- Defect escape rate < 5%
- Generator/evaluator separation enforced

## Dependencies

**Requires:** P0-3 Verification (as the review mechanism)
**Interacts with:** P2-1 Automated Linters — linters handle style, auditors handle semantics
