# P2-3. AI Auditors & Collaboration Channels

> **Chain:** [EP-16](../principles/EP-16.md) → No author is their own best reviewer

## L2: Targeted Enhancement

Every substantial output is independently reviewed before merging.

## L3: Design Decisions

Automated code review (agent-as-reviewer); defined review criteria (correctness, style, security, architecture); generator/evaluator separation; escalation to human for ambiguous cases; review feedback loops.

## L4: Concrete Actions & Tools

- **Action:** Assign dedicated reviewer agents that audit code quality independently from the generating agent.
- **Action:** Peer-review by auditor agents; collaboration channels between MAS roles; automated audit trails; machine-readable audit reports; Machine-Readability First.
- **Action:** Enforce generator/evaluator separation — the agent that writes the code should not be the same agent that approves it.
- **Tool:** Agent-as-reviewer configurations.
- **Tool:** PR review automation tools.
- **Tool:** Collaboration channels (shared review logs, comment feeds).

## L4: Prevention

- **`P2-3` Prevent Self-Grading:** You must prevent implementation agents from grading their own work. All major changes must be reviewed and certified by a dedicated auditor agent with different system instructions.
- **`P2-3` Prevent Narrative Audit Findings:** Audit reports and collaboration logs must follow a machine-readable JSON format (e.g. SARIF) to enable automated remediation and tracking.

## L5: Gap Signals

- Agent-generated code is never independently reviewed
- Same agent- Implementation agents introduce errors that go undetected
- No audit trail of peer-review or collaboration in MAS
- Auditor agents identify issues but they are not remediated
- Feedback loops between agents are too long or ambiguous
- **Narrative Markdown tables in improvement policies (violating P1-1)**
