# P0-11. Portable Agent Surface

> **Chain:** [EP-10](../principles/EP-10.md) → Portability over proprietary convenience

## L2: Targeted Enhancement

Agent instructions are discoverable and functional from any IDE.

## L3: Design Decisions

Single AGENTS.md as canonical surface; IDE-specific files as thin shims; bootstrap recipe (AGENTS.md → subfolder AGENTS.md → first linter → first structural test → initial roles).

## L4: Concrete Actions & Tools

- **Action:** Maintain a single `AGENTS.md` at the repository root containing all IDE-agnostic harness rules (purpose, layout, workflows, tools, forbidden operations, conventions).
- **Action:** Reduce IDE-specific files (`CLAUDE.md`, `.cursorrules`, `.github/copilot-instructions.md`, `.windsurfrules`) to thin shims that reference `AGENTS.md` and contain only IDE-specific overrides.
- **Action:** Never store project-wide rules exclusively in an IDE's proprietary memory system.
- **Action:** For cold-start bootstrapping, follow a **Bootstrap Recipe**: (1) create `AGENTS.md` (~100 lines); (2) add subfolder `AGENTS.md` files; (3) add the first custom linter rule; (4) add the first structural test; (5) define 4–6 initial agent roles.
- **Tool:** Template `AGENTS.md` with standard sections.
- **Tool:** CI check verifying `AGENTS.md` exists and each IDE shim file contains a canonical reference pointer.

## L4: Prevention

- **`P0-11` Prevent IDE-Locked Rules:** You must prevent global project rules from living exclusively in one IDE's proprietary format. Rules stored this way are invisible to agents running in other environments, fragmenting the harness across IDEs. Prevent this by mandating a single `AGENTS.md` as the canonical rule surface, with IDE-specific files serving as thin shims.

## L5: Gap Signals

- `AGENTS.md` does not exist at the repository root
- `CLAUDE.md` or `.cursorrules` contains project-wide rules not replicated in an IDE-agnostic file
- IDE-specific files contain substantive harness rules instead of pointers to a canonical source
- Project rules are stored in an IDE's proprietary memory system invisible to other IDEs
- Switching IDEs requires manually re-creating the agent instruction surface

## L5: Improvement Policies

| Tier | Action | Dimensions |
| ------ | -------- | ------------ |
| 1 | Create AGENTS.md at repo root with all IDE-agnostic harness rules | Maturity, Risk |
| 1 | Refactor IDE-specific files to thin shims referencing AGENTS.md | Effectiveness |
| 2 | Add CI lint check verifying AGENTS.md exists and shim files contain canonical reference pointer | Risk, Scalability |
| 3 | Auto-generate IDE shim files from AGENTS.md template during CI | Scalability, Cost |

## L5: Measurement

- 0 IDE-specific-only rules
- All rules accessible from ≥ 3 IDE environments
- IDE switch requires 0 manual rule recreation

## Dependencies

**Requires:** P1-1 Repository as Truth (for content)
**Enables:** P0-6 Rippable Middleware philosophy — IDE integration layers are independently swappable
