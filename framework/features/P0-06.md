# P0-6. Rippable Middleware

> **Chain:** [EP-6](../principles/EP-06.md) → Scaffolding is temporary by design

## L2: Targeted Enhancement

Any harness layer can be removed without breaking the rest.

## L3: Design Decisions

Composable, independently removable mMiddleware pattern (express/koa style) for LLM tools; standardized call/response protocol; modular prompt headers; plugin-based agent capabilities; Machine-Readability First.

## L4: Concrete Actions & Tools

- **Action:** Refactor harness into composable, independently removable layers.
- **Action:** Add feature flags to toggle middleware components on/off.
- **Action:** Regularly audit middleware relevance against current model capabilities.
- **Tool:** Feature flag configuration files.
- **Tool:** Middleware dependency graphs.

## L4: Prevention

- **`P0-6` Prevent Monolithic Harnesses:** No harness component should be direct-coupled. Every layer must interact through an standard interface (the "Harness Protocol") so any tier can be updated or replaced without breaking others.
- **`P0-6` Prevent Narrative Middleware Specs:** Middleware definitions and tool schemas must be provided in machine-readable JSON Schema formats.
- **`P0-6` Prevent Over-Engineering the Control Flow:** You must prevent the harness from becoming a brittle, static cage. Hardcoding overly complex pipelines will break when underlying models naturally improve. Prevent this by building "rippable" middleware that can be easily removed.

## L5: Gap Signals

- Harness logic is monolithic and tightly coupled
- Unable to remove a tool without refactoring core agent logic
- Middleware failure crashes the entire agent session
- Tightly-coupled harness layers prevent modular upgrades
- No versioning of prompts vs. tools
- Narrative Markdown tables in improvement policies (violating P1-1)
