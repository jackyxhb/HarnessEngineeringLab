# P1-9. Branch-Based Cognitive Memory

> **Chain:** [EP-2](../principles/EP-02.md) → State must outlive the session

## L2: Targeted Enhancement

Complex objectives decompose into checkpointed sub-tasks with cognitive history that survives context resets and enables parallel execution.

## L3: Design Decisions

Task partitioning via Git branches; explicit "approval of evidence" commit messages; recursive merging of sub-tasks; machine-readable task traces; branch naming conventions as cognitive addressability; Machine-Readability First. **MAS implication:** In multi-agent systems, the orchestrator dispatches sub-tasks to agent-specific branches in parallel; each agent's commit history forms an independent evidence chain that merges back into the parent task branch.

## L4: Concrete Actions & Tools

- **Action:** Decompose complex objectives into discrete, atomic sub-tasks and execute each in an isolated tracking branch.
- **Action:** Enforce branch naming conventions (`task/[issue-id]-[concise-description]` or `subtask/[parent-name]-[feature]`) so that branch names serve as machine-readable cognitive addresses for task context.
- **Action:** Generate structured "approval of evidence" commits that explain _what_ was done, _why_ it resolves the sub-task, and _what evidence_ confirms correctness.
- **Action:** Before merging a sub-task branch, verify that all quality gates pass (`npm run check`) and no regressions were introduced.
- **Action:** After all sub-tasks merge to the parent, merge the parent into the root development branch to seal the cognitive memory structure.
- **Action:** Clean up merged sub-task branches to prevent stale branch accumulation (P3-1 entropy control).
- **Tool:** Git Worktrees for concurrent branch execution without workspace switching.
- **Tool:** `/cognitive-branch` workflow — enforces the three-phase partition-execute-merge cycle.
- **Tool:** Branch-name sensor (pre-commit or CI gate) — validates branch naming conventions before allowing commits, ensuring cognitive addressability is mechanically enforced.

## L4: Prevention

- **`P1-9` Prevent Monolithic Task Failures:** You must prevent agents from attempting large, complex tasks in a single unbroken stream. Mandate the use of `/cognitive-branch` to partition work and build traceable progress history.
- **`P1-9` Prevent Narrative Cognitive History:** Branch-based task traces and approval-of-evidence records must be stored in a machine-readable JSON format to enable automated task-resumption and audit.
- **`P1-9` Prevent Unnamed or Misnamed Branches:** Branch names must follow the prescribed naming convention. Unnamed or convention-violating branches break cognitive addressability and prevent automated task-resumption.

## L5: Gap Signals

- Agent processes multi-step complex objectives holistically in a monolithic branch
- No checkpointed cognitive history for distinct sub-tasks
- Sub-tasks are executed sequentially rather than concurrently when they could be parallelized
- Commit messages are sparse and lack structured evidentiary value
- Branch names do not follow a naming convention, making task context unrecoverable from branch alone
