# P1-9. Branch-Based Cognitive Memory

> **Chain:** [EP-2](../principles/EP-02.md) → State must outlive the session

## L2: Targeted Enhancement

Complex objectives decompose into checkpointed sub-tasks with cognitive history.

## L3: Design Decisions

Task partitioning via Git branches; explicit "approval of evidence" commit messages; recursive merging of sub-tasks; machine-readable task trace-recursive memory; Machine-Readability First.

## L4: Concrete Actions & Tools

- **Action:** Split complex objectives into subtasks, execute each in a new branch concurrently, and merge back to the parent task branch.
- **Tool:** Git Worktrees and Concurrent Branch Management scripts.

## L4: Prevention

- **`P1-9` Prevent Monolithic Task Failures:** You must prevent agents from attempting large, complex tasks in a single unbroken stream. Mandate the use of `/cognitive-branch` to partition work and build traceable progress history.
- **`P1-9` Prevent Narrative Cognitive History:** Branch-based task traces and approval-of-evidence records must be stored in a machine-readable JSON format to enable automated task-resumption and audit.

## L5: Gap Signals

- Agent processes multi-step complex objectives holistically in a monolithic branch
- No checkpointed cognitive history for distinct sub-tasks
- Sub-tasks are executed sequentially rather than concurrently when they could be parallelized
- Commit messages are sparse and lack structured evidentiary value
