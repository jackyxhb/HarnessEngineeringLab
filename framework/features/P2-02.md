# P2-2. Dependency Enforcement

> **Chain:** [EP-15](../principles/EP-15.md) → Mechanical enforcement over advisory guidance

## L2: Targeted Enhancement

Architectural boundaries mechanically enforced, not just documented.

## L3: Design Decisions

Import/dependency graph analysis; module boundary definitions; structural tests; approved dependency lists with automated auditing.

## L4: Concrete Actions & Tools

- **Action:** Enforce architectural boundaries through automated dependency analysis (no circular imports, module boundary violations, or unauthorized dependencies).
  - **Tool:** `madge` ([madge](https://github.com/pahen/madge)) — Dependency graph analysis; detects circular imports, visualizes module relationships.
  - **Tool:** Configuration file: `.harness/dependency-config.json` — Machine-readable dependency boundary rules (JSON schema).
  - **Tool:** Pre-commit hook via `husky` to run madge validation on each commit.
  - **Acceptance Criteria:** All circular dependencies detected within 5 seconds; false-negative rate ≤ 0%; false-positive rate ≤ 2%; violations block commit via pre-commit hook.

- **Action:** Define allowed and forbidden dependency paths in machine-readable configuration.
  - **Tool:** `.harness/dependency-whitelist.json` — JSON schema defining: allowed-paths (module→module), forbidden-paths (module→module), boundary-zones (layer definitions).
  - **Tool:** CI gate script: `scripts/validate-dependencies.js` — Reads whitelist and checks dependency graph against rules.
  - **Acceptance Criteria:** Whitelist enforces 100% of documented architectural boundaries; CI rejects PRs with boundary violations; validation completes in < 10 seconds.

- **Action:** Automated circular dependency detection and reporting.
  - **Tool:** `eslint-plugin-import` rule `no-cycle` or equivalent (or standalone via madge --circular).
  - **Tool:** JSON report output: `.harness/dependency-violations-report.json` — Machine-readable format: `{ "violations": [ { "type": "circular", "modules": [...], "severity": "error" } ] }`.
  - **Acceptance Criteria:** All circular dependencies reported in JSON format; report available within 10 seconds; zero false negatives on test suite with 50+ known violations.

- **Action:** Enforcement gate preventing violations from reaching main branch.
  - **Tool:** GitHub Actions CI gate (`.github/workflows/dependency-check.yml`) — Runs `scripts/validate-dependencies.js` + madge on PR; blocks merge on violations.
  - **Tool:** Pre-commit hook (via `.husky/pre-commit`) — Runs dependency check before commit; can be bypassed with `--no-verify` only by explicit user action.
  - **Acceptance Criteria:** 100% of PRs with dependency violations are blocked before merge; pre-commit hook prevents 98%+ of violations from leaving developer machine; escalation events recorded in `.harness/escalation-events.jsonl` when violations are auto-rejected.

## L4: Prevention

- **`P2-2` Prevent Boundary Overreach:** You must prevent agents from importing cross-layer modules that bypass established architectural patterns (e.g. bypassing a repository to access a database directly). Prevent this using `dependency-cruiser` rules or structural tests.
- **`P2-2` Prevent Narrative Architecture Maps:** Architectural boundary definitions and dependency white-lists must be stored in machine-readable JSON/YAML to allow CI enforcement.

## L5: Gap Signals

- Circular dependencies exist unchecked
- Agent imports modules that violate architectural boundaries
- Dependency conflicts not detected until runtime
- No automated validation of module boundary rules
