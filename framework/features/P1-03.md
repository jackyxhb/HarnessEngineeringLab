# P1-3. Tool Offloading

> **Chain:** [EP-12](../principles/EP-12.md) → Finite attention demands active management

## L2: Targeted Enhancement

Tool outputs never dominate the context window.

## L3: Design Decisions

Head/tail token stripping; full results to filesystem; on-demand retrieval; per-tool token limits.

## L4: Concrete Actions & Tools

- **Action:** Offload complex logic and large outputs to external tools and files.
  - **Tool:** Tool registry: `.harness/tool-definition.schema.json` defines machine-readable tool manifest with fields: `name`, `command`, `input_type`, `output_type`, `token_limit`, `timeout_ms`.
  - **Tool:** Output truncation strategy: HEAD/TAIL stripping — for tool outputs > 2000 tokens, write full output to `.harness/tool-outputs/<tool_id>_<timestamp>.json`, return only first 100 tokens (HEAD) + last 100 tokens (TAIL) + "... [output truncated, see .harness/tool-outputs/...]" marker.
  - **Acceptance Criteria:** No tool output > 2000 tokens inline in context; full output always retrievable on-demand; truncation marker visible in context.

- **Action:** Implement standardized tool interfaces for reproducibility.
  - **Tool:** Tool interface contract: each tool accepts JSON input, returns JSON output with structure `{ "status": "success|error", "data": <result>, "token_count": <count>, "truncated": boolean }`.
  - **Acceptance Criteria:** All tools follow the same interface; agent can discover and invoke any tool using the standard interface.

- **Action:** Build machine-readable tool manifests for dynamic discovery.
  - **Tool:** `.harness/mcp-capabilities.json` registry: lists all available tools/scripts with: `id`, `command`, `description`, `input_schema`, `output_schema`, `token_limit`.
  - **Tool:** Tool discovery logic: agent reads `.harness/mcp-capabilities.json` at startup to populate available tools; no hardcoded tool lists.
  - **Acceptance Criteria:** Agent can list all available tools from `.harness/mcp-capabilities.json` without hardcoding; new tools automatically discoverable after adding to registry.

## L4: Prevention

- See P1-2 prevention: Context Rot prevention applies jointly to P1-2 and P1-3.

## L5: Gap Signals

- Agent spends reasoning tokens on logic that could be a script
- Tool interfaces are inconsistent across different tasks
- Agent fails to discover available tools in the harness
- Hallucinations occur during complex in-context calculations
