# P0-7. Escalation Policies & Audit Trails

> **Chain:** [EP-7](../principles/EP-07.md) → Every action must be traceable

## L2: Targeted Enhancement

Every agent action is attributable; stuck agents are detected and escalated within defined time bounds.

## L3: Design Decisions

Centralized audit logging; tiered alert levels (Slack, PagerDuty); loop-detection heartbeats; human-in-the-loop (HITL) triggers on high-entropy states; Machine-Readability First.

## L4: Concrete Actions & Tools

- **Action:** Define escalation triggers (N consecutive test failures, time limits, loop detection).
- **Action:** Route stuck tasks to human via notification (Slack, email, dashboard).
- **Action:** Implement tiered escalation (retry → different agent → human).
- **Tool:** Notification integrations (Slack, email, dashboard alerts).
- **Tool:** Audit trail logging systems.

## L4: Prevention

- **`P0-7` Prevent Silent Looping:** Every agent must emit a 'heartbeat' signal that is monitored by an external orchestrator or cron job. If the agent remains in an 'active' state for longer than its assigned time-slice without progress, the orchestrator must terminate the session and alert a human.
- **`P0-7` Prevent Narrative Audit Trails:** All audit logs must be JSON-standardized to enable automated anomaly detection and trend analysis.

## L5: Gap Signals

- Agent loops indefinitely on unsolvable problems
- No notification when agent is stuck
- Human discovers failures hours or days later
- No defined threshold for "stuck" vs. "still working"
