# P1-12. Skill Engineering

> **Chain:** [EP-12](../principles/EP-12.md) → Finite attention demands active management

## L2: Targeted Enhancement

Agent skills are modular, context-efficient, and tunable.

## L3: Design Decisions

Mandatory-read budget per skill file (<200 lines); routing-hub pattern in skill orchestrator; monolith→module splits isolating framework layers; decision-tree routing; Disciplined construction of agent action spaces; prompt engineering; tool definition optimization; machine-readable skill capability maps; Machine-Readability First.

## Scope: SAS vs MAS

**SAS Scope:** Single-agent skills operate with minimal context efficiency requirements — a single agent can load larger reference files if task specialization demands it. Mandatory-read budget remains <200 lines for ergonomics, but the pressure is lower. Template reuse and decision-tree routing optimize within-agent efficiency (avoiding redundant re-reads during subtasks).

**MAS Scope:** Multi-agent skill engineering demands strict <200 line budgets across all reference files because multiple agents can be spawned concurrently, each loading multiple skill files into context. Routing hubs and decision-tree patterns become critical to minimize aggregate context load across the agent pool. Subagent dispatch prompts must include pre-configured orchestration instructions so spawned agents don't re-derive coordination logic.

**Transition Path:** SAS implementations should enforce <200 line budgets and routing-hub patterns now, even if only one agent exists. These patterns are costless when agents are sequential but essential when scaling to MAS. Design skill files for parallel spawn scenarios in mind; the skill interface itself should require no modification when agents become concurrent.

## L4: Concrete Actions & Tools

- **Action:** Split monolithic skill reference files into modular components to keep each file below a mandatory-read budget (<200 lines).
  - **Tool:** File-length linter: `npm run lint:skill-size -- <skill-dir>` — scans all `.md` files in skill directory, reports files > 200 lines with line count. Acceptance: linter exits 0 only if all files ≤ 200 lines; violations block pre-commit hook.
  - **Tool:** Skill file splitter script: `.agent/workflows/split-skill-file.js` — accepts `{input_file, split_points: [line_nums]}`, generates named output files (e.g., `skill-routing-hub.md`, `skill-reference-auth.md`), updates cross-links. Acceptance: output files conform to <200 line limit; internal cross-references use relative paths in format `(see ../reference-auth.md)`.

- **Action:** Transform the skill orchestrator (e.g., `SKILL.md`) into a routing hub with a decision tree that directs agents to the correct reference file without scanning the full skill surface.
  - **Tool:** Routing-hub template: `.agent/skills/{skill_name}/SKILL.md` — structure: `# Routing Hub` → `## Decision Tree` → `### Branch: "user wants X"` → list reference files agents should load → `## Quick Links` → file index. Acceptance: agents can determine which 1-3 reference files to load by reading only SKILL.md (≤150 lines).
  - **Tool:** Decision-tree validator: `npm run validate:skill-routing -- <SKILL.md>` — verifies every decision-tree branch has ≥ 1 reference file link; checks all linked files exist; ensures no unreachable reference files. Acceptance: validator exits 0; missing links or orphan files trigger pre-commit failure.

- **Action:** Reduce mandatory context load per action path by extracting utilities, checklists, and templates into dedicated files agents load only when needed.
  - **Tool:** Context-load auditor: `.agent/workflows/audit-mandatory-read.js` — traces an action path through skill decision tree, sums line counts of all files agents must read before first action. Acceptance: audit reports ≤ 300 total lines for standard paths; flags paths > 400 lines as context-risk.
  - **Tool:** Extracted checklists directory: `.agent/skills/{skill_name}/checklists/` — each `.json` file contains: `{checklist_id, title, items: [{step, instruction, acceptance_criteria}]}`. Accepted formats: pre-commit linter validates against `.harness/checklist.schema.json`.
  - **Tool:** Extracted templates directory: `.agent/skills/{skill_name}/templates/` — each `.txt` or `.json` template is standalone and referenced by name, not inlined. Acceptance: skill reference files reference templates by name only (e.g., "see template: task-state-record"); agents load template files on-demand.

- **Action:** Standardize terminology across all skill files to prevent logic errors in subagent dispatches.
  - **Tool:** Terminology glossary: `.agent/skills/{skill_name}/GLOSSARY.md` — structured list `## Term` → definition → usage examples. Acceptance: all skill reference files use glossary terms consistently; linter checks for homonyms or undefined terms.
  - **Tool:** Term consistency checker: `npm run lint:terminology -- <skill-dir>` — scans all files, flags uses of non-glossary synonyms (e.g., "agent" vs "subagent" vs "worker"). Acceptance: linter reports violations; pre-commit hook fails if new terms introduced without glossary entry.

- **Action:** Extract reusable output templates into a dedicated `templates/` directory.
  - **Tool:** Template catalog: `.agent/skills/{skill_name}/templates/` — registry file `.index.json`: `{templates: [{id, filename, description, schema_binding: ".harness/schema-name.json"}]}`. Acceptance: every template has a schema binding; `npm run validate:templates -- <skill_dir>` confirms all templates conform to bound schemas.

- **Action:** Pre-build subagent dispatch prompts containing pre-configured orchestration instructions for parallel agent workflows.
  - **Tool:** Subagent dispatch template: `.agent/skills/{skill_name}/templates/subagent-dispatch-prompt.txt` — includes: agent role, task context, which reference files to load, which templates to use, timeout, escalation points. Acceptance: prompt is <500 tokens; agents spawned with this prompt do not re-derive coordination logic.
  - **Tool:** Dispatch injector script: `.agent/workflows/inject-dispatch-prompt.js` — accepts `{base_task, subagent_roles: ["role1", "role2"]}`, generates individual dispatch prompts pre-injecting task context and tool allowlists per role. Acceptance: each subagent receives only the prompts and tool list they need; no shared context bloat.

## L4: Prevention

- **`P1-12` Prevent Tool Definition Entropy:** You must prevent the creation of redundant or overlapping tool definitions. Every new tool must be audited for uniqueness and high-signal interface design, with the checked-in manifest projection conforming to `.harness/tool-definition.schema.json`.
- **`P1-12` Prevent Narrative Skill Architecture:** Skill definitions and prompt templates must follow machine-readable manifest projections conforming to `.harness/skill-manifest.schema.json` and `.harness/tool-definition.schema.json` to ensure automated generation and validation.

## L5: Gap Signals

- Agent fails to understand complex or ambiguous tool interfaces
- Tool results are not optimized for agent parsing (token waste)
- Skill instructions are too long and cause context rot
- No systematic way to test or evaluate skill effectiveness
- Skills ship as monolithic documents combining unrelated procedures, templates, and references
- Terminology varies across skill files with no canonical glossary
- Repeated boilerplate across skill files that could be extracted into reusable templates
- Agents waste tokens reading skill context irrelevant to the current task
