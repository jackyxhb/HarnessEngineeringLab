# P1-12. Skill Engineering

> **Chain:** [EP-12](../principles/EP-12.md) → Finite attention demands active management

## L2: Targeted Enhancement

Agent skills are modular, context-efficient, and tunable.

## L3: Design Decisions

Mandatory-read budget per skill file (<200 lines); routing-hub pattern in skill orchestrator; monolith→module splits isolating framework layers; decision-tree routing; template extraction; subagent dispatch prompts; terminology standardization.

## L4: Concrete Actions & Tools

- **Action:** Split monolithic skill reference files into modular components to keep each file below a mandatory-read budget (<200 lines).
- **Action:** Transform the skill orchestrator (e.g., `SKILL.md`) into a routing hub with a decision tree that directs agents to the correct reference file without scanning the full skill surface.
- **Action:** Reduce mandatory context load per action path by extracting utilities, checklists, and templates into dedicated files agents load only when needed.
- **Action:** Standardize terminology across all skill files to prevent logic errors in subagent dispatches.
- **Action:** Extract reusable output templates into a dedicated `templates/` directory.
- **Action:** Pre-build subagent dispatch prompts containing pre-configured orchestration instructions for parallel agent workflows.
- **Tool:** File-length linters enforcing the <200 line budget per skill reference file.
- **Tool:** Decision-tree routing patterns in skill orchestrators.
- **Tool:** Template libraries for standardized skill outputs.

## L4: Prevention

- **`P1-12` Prevent Monolithic, Unstructured Skills:** You must prevent agent skills from shipping as monolithic reference files that exceed mandatory-read budgets or lack routing logic. Monolithic skills force agents to read hundreds of lines before finding the correct action path, causing context waste and degraded reasoning.

## L5: Gap Signals

- Agent skill files exceed 200 lines, forcing agents to read far more context than needed
- No routing hub or decision tree — agents must scan the entire skill reference
- Skills ship as monolithic documents combining unrelated procedures, templates, and references
- Terminology varies across skill files with no canonical glossary
- Repeated boilerplate across skill files that could be extracted into reusable templates
- Agents waste tokens reading skill context irrelevant to the current task

## L5: Improvement Policies

| Tier | Action | Dimensions |
| ------ | -------- | ------------ |
| 1 | Enforce a mandatory-read budget: every skill file's always-loaded preamble must stay under 200 lines | Effectiveness, Cost |
| 1 | Split monolithic skill references into modular sub-files organized by action path | Effectiveness, Maturity |
| 2 | Add a routing-hub pattern (decision-tree or dispatcher) that directs agents to the correct sub-file | Effectiveness, Scalability |
| 2 | Standardize terminology across all skill files — publish canonical vocabulary and enforce via linter | Maturity, Risk |
| 2 | Extract repeated patterns into template libraries that skill files import rather than duplicate | Cost, Scalability |
| 3 | Pre-build subagent dispatch prompts per skill so orchestrators can delegate without re-reading | Scalability, Cost |

## L5: Measurement

- Mandatory read per action path reduced 40-60%
- All skill reference files <200 lines
- Time-to-first-action measurably improved

## Dependencies

**Complements:** P1-3 Tool Offloading — well-engineered skills make tool selection more precise
**Enhances:** P1-7 Planning — agents with modular skills produce better-scoped plans
