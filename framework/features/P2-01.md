# P2-1. Automated Linters

> **Chain:** [EP-15](../principles/EP-15.md) → Mechanical enforcement over advisory guidance

## L2: Targeted Enhancement

Zero style/type/structural violations reaching the main branch.

## L3: Design Decisions

Pre-commit hooks (lint, type-check, structural tests); custom linters for harness invariants; CI binary pass/fail gates; shift-left cost stratification.

## L4: Concrete Actions & Tools

- **Action:** Gate every commit with automated tests, linters, type-checkers, and structural tests that enforce architectural constraints mechanically.
- **Action:** Add custom linters for harness-specific invariants (e.g., `he-lint.js` for feature counts, pillar labels, file naming).
- **Tool:** Pre-commit hooks (husky, lint-staged).
- **Tool:** CI pipelines (GitHub Actions) with binary pass/fail gates.
- **Tool:** Custom linters (`he-lint.js`, markdownlint, cspell).

## L4: Prevention

- **`P2-1` Prevent Guide-Only Features (Unenforced Rules):** You must prevent AGENTS.md rules, templates, or prompts from shipping without a corresponding enforcement sensor (lint rule, structural test, or CI check). A guide without a sensor is an unenforced wish that agents will ignore.

## L5: Gap Signals

- Agents commit code that violates project style guidelines
- No pre-commit or CI validation
- Architectural constraints are documented but not enforced
- Rules in AGENTS.md have no corresponding mechanical enforcement

## L5: Improvement Policies

| Tier | Action | Dimensions |
| ------ | -------- | ------------ |
| 1 | Install pre-commit hooks with linting, type-checking, and formatting | Maturity |
| 1 | Add CI pipeline with binary pass/fail gates | Risk |
| 2 | Add custom structural linters for harness-specific invariants | Effectiveness |
| 2 | Audit guide/sensor parity every sprint — flag orphaned guides | Scalability |
| 3 | Build auto-fix capabilities into linters | Cost |

## L5: Measurement

- 0 style/type violations on main branch
- Guide/sensor parity > 90%
- Pre-commit hook bypass rate → 0

## Dependencies

**Enables:** P3-3 Pattern Auditing — linters are the enforcement mechanism
**Enforces standards from:** P1-1 Repository as Truth
