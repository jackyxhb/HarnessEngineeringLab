# P3-2. Documentation Sync

> **Chain:** [EP-19](../principles/EP-19.md) → Documentation must live with the code

## L2: Targeted Enhancement

Documentation always matches the current state of the code.

## L3: Design Decisions

Docs-as-code; co-located documentation; automated staleness detection; doc update triggers on code changes.

## L4: Concrete Actions & Tools

- **Action:** Ensure documentation is updated in the same commit/PR as the code it describes.
- **Action:** Implement automated staleness detection — alert when docs diverge from code.
- **Action:** Co-locate documentation with the code modules it describes whenever possible.
- **Tool:** Documentation linters (markdownlint, link checkers).
- **Tool:** CI checks verifying doc freshness.

## L4: Prevention

- **`P3-2, P3-4` Prevent Documentation Disconnects (Missing Consolidation):** You must prevent core system counts and architectural records from drifting out of sync. Prevent this by implementing a Consolidation Loop that auto-updates documentation as features land.

## L5: Gap Signals

- Documentation describes features that no longer exist
- Code changes land without corresponding doc updates
- README is perpetually outdated
- Developer documentation contradicts actual code behavior

## L5: Improvement Policies

| Tier | Action | Dimensions |
| ------ | -------- | ------------ |
| 1 | Mandate doc updates in the same commit/PR as code changes | Maturity |
| 1 | Add documentation linting to CI pipeline | Risk |
| 2 | Build automated staleness detection (doc → code divergence alerts) | Effectiveness |
| 2 | Co-locate docs with code modules | Scalability |
| 3 | Implement auto-generated documentation from code comments and types | Cost |

## L5: Measurement

- Doc-to-code divergence age < 1 sprint
- Stale documentation count → 0
- 100% of code PRs include doc updates when applicable

## Dependencies

**Requires:** P1-1 Repository as Truth (for doc standards)
**Feeds:** P3-4 Consolidation Loop
