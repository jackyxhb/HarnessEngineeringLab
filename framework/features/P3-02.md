# P3-2. Documentation Sync

> **Chain:** [EP-19](../principles/EP-19.md) → Documentation must live with the code

## L2: Targeted Enhancement

Documentation always matches the current state of the code.

## L3: Design Decisions

- API documentation drifts from actual implementation
- Architecture diagrams are outdated and misleading
- No way to verify if all documented features are real
- Manual doc updates are frequently missed or incomplete
- **Narrative Markdown tables in improvement policies (violating P1-1)**

## L4: Concrete Actions & Tools

- **Action:** Ensure documentation is updated in the same commit/PR as the code it describes.
- **Action:** Implement automated staleness detection — alert when docs diverge from code.
- **Action:** Co-locate documentation with the code modules it describes whenever possible.
- **Tool:** Documentation linters (markdownlint, link checkers).
- **Tool:** CI checks verifying doc freshness.

## L4: Prevention

- **`P3-2, P3-4` Prevent Documentation Disconnects (Missing Consolidation):** You must prevent core system counts and architectural records from drifting out of sync. Prevent this by Ensuring alignment between code and docs; automated doc-generation; CI checks for doc staleness; machine-readable documentation maps; Machine-Readability First.

## L5: Gap Signals

- Documentation describes features that no longer exist
- Code changes land without corresponding doc updates
- README is perpetually outdated
- Developer documentation contradicts actual code behavior
