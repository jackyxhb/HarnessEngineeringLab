# P1-5. Observability / Dashboards

> **Chain:** [EP-8](../principles/EP-08.md) → You cannot improve what you do not measure

## L2: Targeted Enhancement

Agents and humans have real-time visibility into system behavior and health.

## L3: Design Decisions

CI/CD status exposure to agents; harness structural integrity as signal category; task-ID artifact storage; dedicated OBSERVABILITY.md spec.

## L4: Concrete Actions & Tools

- **Action:** Serve real-time system states as dynamic context so agents can observe their own work.
- **Action:** Track harness structural integrity as a dedicated signal category: verify required file existence, workflow registry completeness, and pre-commit hook liveness.
- **Action:** Implement **task-ID artifact storage**: each agent task produces outputs keyed by a unique task identifier, forming an inspectable audit trail.
- **Tool:** Logs, metrics, traces, screenshots, and live CI/CD pipeline statuses.
- **Tool:** Agent Performance Monitoring Dashboards for human oversight.
- **Tool:** `docs/OBSERVABILITY.md` — minimum observable field spec defining all signal sources, targets, alert thresholds, and recovery procedures.

## L4: Prevention

- **`P1-5` Prevent Blind Execution:** You must prevent agents from performing actions without clear, observable signals. Every command must produce an audit trail that can be verified by a separate auditor agent.
- **`P1-5` Prevent Narrative Observability Metrics:** Performance metrics and audit summaries must be stored in machine-readable JSON format to enable automated dashboarding and alerting.

## L5: Gap Signals

- No visibility into agent error rates or logic failures
- Hard to track collective progress in multi-agent workflows
- Manual reviews required to understand agent performance drifts
- No real-time alerting for critical harness failures
- Human engineers fly blind on agent behavior patterns
