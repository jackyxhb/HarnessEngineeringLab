# P0-1. Bash Sandboxes

> **Chain:** [EP-1](../principles/EP-01.md) → Isolation prevents contamination

## L2: Targeted Enhancement

Zero cross-contamination between agent execution environments.

## L3: Design Decisions

Isolated containers/VMs per agent session; pre-installed language runtimes, test runners, CLI tools; visual monitoring of sandbox state (tmux, split-pane terminals).

## L4: Concrete Actions & Tools

- **Action:** Provision safe, scalable, isolated execution environments for every agent session.
- **Tool:** General-purpose bash execution tools.
- **Tool:** Sandboxes pre-installed with language runtimes (Node.js, Python, Go), test runners (Jest, pytest), and CLI tools (git, npm, docker).
- **Tool:** Visual split-pane terminals (tmux) for real-time monitoring of sandbox state.

## L4: Prevention

- **`P0-1` No prevention items defined.** Sandbox isolation is a foundational enabler; its absence is caught by gap signals below.

## L5: Gap Signals

- Agents execute code on the developer's local machine
- No isolation between agent sessions
- Agent cannot install packages or run arbitrary commands
- Failures in one agent's execution corrupt another's environment

## L5: Improvement Policies

| Tier | Action | Dimensions |
| ------ | -------- | ------------ |
| 1 | Provision isolated containers or VMs per agent session | Risk, Maturity |
| 1 | Pre-install language runtimes, test runners, and CLI tools in sandbox images | Effectiveness |
| 2 | Enable visual monitoring of sandbox state (tmux, split-pane terminals) | Human Role |
| 3 | Auto-scale sandbox pools based on concurrent agent demand | Scalability, Cost |

## L5: Measurement

- 0 environment collision incidents per sprint
- 0 cross-agent state leaks
- Agent can install/execute arbitrary packages without affecting peers

**Required by:** P0-3 Verification, P0-5 Orchestration, P1-3 Tool Offloading, P1-6 Web Search, P3-1 Scheduled Cleanups
