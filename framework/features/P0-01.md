# P0-1. Bash Sandboxes

> **Chain:** [EP-1](../principles/EP-01.md) → Isolation prevents contamination

## L2: Targeted Enhancement

Zero cross-contamination between agent execution environments.

## L3: Design Decisions

Isolated containers/VMs per agent session; pre-installed language runtimes, test runners, CLI tools; visual monitoring of sandbox state (tmux, split-pane terminals); Ephemeral State Management; Determinism.

> **P0-1 ↔ P0-2 Reconciliation:** Sandboxes are ephemeral (reset after each session), but all agent work products are persisted through Git (P0-2) before the sandbox resets. Ephemeral execution + durable versioned output are complementary, not contradictory.

## L4: Concrete Actions & Tools

- **Action:** Provision safe, scalable, isolated execution environments for every agent session.
  - **Tool:** Sandbox Technology: Docker containers (`docker run --rm -v $(pwd):/workspace -w /workspace <image>`) for ephemeral workspaces, or VM snapshots for deeper isolation.
  - **Acceptance Criteria:** Each agent session gets an isolated environment that resets after task completion; no environment variables or files persist across sessions.

- **Action:** Pre-install language runtimes, test runners, and essential CLI tools in sandbox base images.
  - **Tool:** Base sandbox images with: Node.js (v20+), Python (3.11+), Go (1.21+), Rust (latest stable), bash/sh, git, npm, pip, cargo, grep, sed, awk, jq.
  - **Tool:** Test runners: Jest (npm), pytest (python), Go testing (built-in).
  - **Acceptance Criteria:** All tools available without additional installation; sandbox setup time < 2 seconds for container pull.

- **Action:** Enable real-time monitoring of sandbox execution state.
  - **Tool:** tmux session multiplexer for split-pane terminal display showing: (1) command stdout/stderr, (2) resource usage (CPU, memory, disk I/O via `top`), (3) network activity (via `netstat` or `ss`).
  - **Tool:** Structured logging to `.harness/sandbox-audit.jsonl` capturing: timestamp, command, exit_code, resource_usage, network_egress.
  - **Acceptance Criteria:** Human observer can visually detect any sandbox side-effect within 5 seconds; audit log captures 100% of commands and resource usage.

## L4: Prevention

- **`P0-1` Prevent Persistent Local State:** Every sandbox must be ephemeral and reset to a clean image after each session.
- **`P0-1` Prevent Unmonitored Sandbox State:** Side-effects must be visually or log-detectable (using tmux or split-pane terminals).
- **`P0-1` Prevent Network Bypass:** Sandboxes must have controlled, audited network egress to ensure no non-deterministic data leakage.

## L5: Gap Signals

- Agents execute code on the developer's local machine
- No isolation between agent sessions
- Agent cannot install packages or run arbitrary commands
- Failures in one agent's execution corrupt another's environment
- **Environment persistence across agent sessions (violating P0-1)**
- **Undetected side-effects in unmonitored sandboxes**
