# P0-1. Bash Sandboxes

> **Chain:** [EP-1](../principles/EP-01.md) → Isolation prevents contamination

## L2: Targeted Enhancement

Zero cross-contamination between agent execution environments.

## L3: Design Decisions

### Sandbox Technology Stack
- **Containerization:** Docker 24.x (or later) with libseccomp for syscall filtering; single-use ephemeral containers (`docker run --rm`) torn down after each session.
- **Alternative (deep isolation):** systemd-nspawn (for Linux) or lightweight VMs (QEMU/KVM snapshots) for filesystem-level isolation where container syscall filtering is insufficient.
- **Network Isolation:** Containers run with `--network=isolated` (no external network unless explicitly whitelisted); DNS queries logged to audit trail.
- **Filesystem Isolation:** Bind-mounts workspace at `/workspace` (read-write), all other mounts read-only or absent; `/tmp` and `/home` ephemeral (tmpfs, discarded after session).

### Visual Monitoring Architecture
- **tmux Configuration:** Split pane layout with (1) active shell/output, (2) resource-usage dashboard (`top -p <pid>` updated every 2s), (3) structured audit log tail (`.harness/sandbox-audit.jsonl`).
- **Audit Trail:** All commands, exit codes, resource usage, and network egress logged to `.harness/sandbox-audit.jsonl` in JSON Lines format.
- **Detection SLA:** Human observer can detect unintended side-effects within 5 seconds of occurrence via visual inspection or audit-log query.

### Ephemeral State Management
- **Session Reset:** After task completion, container is destroyed with `docker rm -f <id>`; no volume persistence across sessions.
- **Work Product Capture:** All valuable output (code, logs, reports) must be committed to Git before sandbox destruction (enforcement via pre-destroy hook).
- **Determinism Enforcement:** Same task input → same output, verified by replay test (optional Tier 2).

> **P0-1 ↔ P0-2 Reconciliation:** Sandboxes are ephemeral (reset after each session), but all agent work products are persisted through Git (P0-2) before the sandbox resets. Ephemeral execution + durable versioned output are complementary, not contradictory.

## L4: Concrete Actions & Tools

### Action 1: Provision Isolated Execution Environments

**Mechanism:**
- Deploy Docker 24.x containers with the Dockerfile specification: base image `ubuntu:24.04` or `alpine:latest` (size-optimized), with all tools from L3 pre-installed via distro package managers and language-specific installers.
- Mount workspace at `/workspace` with `--volume $(pwd):/workspace:rw --workdir /workspace --rm`.
- Disable network by default: `--network=isolated` or `--network=none`; whitelist specific egress via `--cap-drop=ALL --cap-add=NET_BIND_SERVICE` for predetermined URLs only.
- Set resource limits: `--memory=2g --cpus=2` (configurable per agent class).
- Enable logging: `--log-driver=json-file --log-opt=max-size=50m` for Docker daemon logs, plus app-level structured logging.

**Provisioning Pipeline:**
1. Build base image once (weekly): `docker build -f Dockerfile.sandbox -t helab/sandbox:v1.0.0 .`
2. Tag image per session: `docker tag helab/sandbox:v1.0.0 helab/sandbox:session-${SESSION_ID}`
3. Run container: `docker run --name agent-${SESSION_ID} [flags] helab/sandbox:session-${SESSION_ID}`
4. Cleanup: `docker rm -f agent-${SESSION_ID}` after exit, with `docker image prune -a --filter "until=7d"` weekly.

**Acceptance Criteria:**
- [ ] Each agent session receives a unique container ID; no state persists across container teardown.
- [ ] Container pulls base image in < 2 seconds (via Docker layer caching).
- [ ] All preinstalled tools are available without additional `apt`, `pip`, `npm`, or `cargo` commands.
- [ ] Network egress is blocked by default (verify via `curl https://example.com` returning 0 bytes or timeout).
- [ ] Resource limits are enforced: a runaway process consuming > 2 GB is killed by kernel OOM handler.

## L4: Prevention

### Prevention Rule 1: Prevent Persistent Local State

**Rationale:** Environment contamination across sessions causes agent failures to cascade (one agent's failing environment corrupts the next agent's execution).

**Rule Statement:** Every sandbox must reset to a clean image after task completion. No environment variables, files, database state, or package cache must persist from one session to the next.

**Enforcement Mechanism:**
- **Binding:** `docker rm -f <container_id>` (mandatory cleanup hook).
- **Registry Entry:** `.harness/prevention-rules-registry.json` record with `rule_id: P0-1-persistent-state`, `binding_status: implemented`, `enforcement_surface: cleanup-hook in scripts/sandbox/cleanup.sh`.
- **Verification:** `npm run audit` includes check: "Container cleanup completed for all sessions in the last 24 hours" (scan Docker event logs).
- **Hook Location:** Pre-commit hook (via `scripts/harness/pre-commit.js`) validates that no `.harness/sandbox-state-*` files are staged (evidence of leaked state).

**Acceptance Criteria for Enforcement:**
- [ ] `docker ps -a | grep -c agent-` returns 0 after cleanup (no dangling containers).
- [ ] `/tmp` and `/home` in next session are empty (verified by `capture-final-state.sh` from previous session).
- [ ] Environment variable inheritance test: start new container, verify `echo $MY_VAR` is empty even if previous session set it.

---

### Prevention Rule 2: Prevent Unmonitored Sandbox State

**Rationale:** Invisible side-effects (silent file modifications, unlogged network calls) lead to non-deterministic failures and security blind spots.

**Rule Statement:** Side-effects must be visually detectable (tmux pane display) or machine-detectable (audit log) within the session in real-time. No command may execute without appearing in the audit trail.

**Enforcement Mechanism:**
- **Binding:** `.harness/sandbox-audit.jsonl` (mandatory JSON audit log, per L4 Action 3).
- **Registry Entry:** `.harness/prevention-rules-registry.json` record with `rule_id: P0-1-unmonitored-state`, `binding_status: implemented`, `enforcement_surface: audit-log at .harness/sandbox-audit.jsonl`.
- **Verification:** Post-session audit: `node scripts/sandbox/audit-completeness-check.js` verifies:
  - Every file modified inside workspace appears in audit log (cross-check inode timestamps against log).
  - Every network call (if egress is whitelisted) is logged with destination, bytes, timestamp.
  - 0 gaps > 5 seconds in audit log tail (ensures monitoring uptime).

**Acceptance Criteria for Enforcement:**
- [ ] tmux panes update without lag; `top` refreshes every 2s, audit tail is live-streaming.
- [ ] Run `touch /workspace/test.txt` in sandbox; verify it appears in audit log within 100ms with inode number.
- [ ] Audit log completeness check exits 0 (no untracked file or network modifications).

---

### Prevention Rule 3: Prevent Network Bypass

**Rationale:** Uncontrolled network egress enables exfiltration, non-deterministic API calls, and side-channel data leakage.

**Rule Statement:** Sandboxes start with `--network=none`. Network access is only enabled for explicitly whitelisted destinations (e.g., npm registry, package repositories). All network I/O is logged to audit trail with source, destination, bytes, and timestamp.

**Enforcement Mechanism:**
- **Binding:** Docker `--network=none` flag + optional iptables/calico policies for whitelisted destinations.
- **Registry Entry:** `.harness/prevention-rules-registry.json` record with `rule_id: P0-1-network-bypass`, `binding_status: implemented`, `enforcement_surface: docker-network-isolation + audit-logging`.
- **Whitelist Management:** File `.harness/sandbox-network-whitelist.json`:

  ```json
  {
    "whitelisted_domains": [
      "registry.npmjs.org",
      "pypi.org",
      "github.com",
      "crates.io"
    ],
    "blocked_attempts_action": "log-and-drop"
  }
  ```

- **Verification:** `scripts/sandbox/test-network-isolation.sh` runs:
  1. `curl https://blocked-domain.com` → expect timeout or refused connection (logged).
  2. `curl https://registry.npmjs.org` (if whitelisted) → expect connection, bytes logged.
  3. Audit log shows both attempts with timestamps.

**Acceptance Criteria for Enforcement:**
- [ ] Container with `--network=none` cannot reach any external IP (verify: `docker run --network=none busybox curl https://example.com` times out).
- [ ] Whitelisted domains are reachable and logged (audit log shows destination, bytes sent/received).
- [ ] Blocked attempts are logged (audit log shows source IP, destination, action=blocked, timestamp).
- [ ] Network audit completeness: 0 undocumented network packets (use `tcpdump` or Docker network inspection).

## L5: Gap Signals

- Agents execute code on the developer's local machine
- No isolation between agent sessions
- Agent cannot install packages or run arbitrary commands
- Failures in one agent's execution corrupt another's environment
- **Environment persistence across agent sessions (violating P0-1)**
- **Undetected side-effects in unmonitored sandboxes**
