# P0-10. Inter-Agent Communication (The Mailbox)

> **Chain:** [EP-5](../principles/EP-05.md) → Coordination cost must stay bounded

## L2: Targeted Enhancement

Agents can coordinate without supervisor bottleneck, with bounded message overhead.

## L3: Design Decisions

Shared message queue/mailbox; Standardized message schema (sender, recipient, payload, threadId); decoupled notification loop; persistent 'Mailbox' in the filesystem; bounded message retry-logic; Machine-Readability First.

## Scope: SAS vs MAS

**SAS Scope:** In single-agent mode, "inter-agent communication" is not applicable — agents operate sequentially without peer messaging. SAS may implement internal message queue for abstract task-dispatch patterns, but no actual inter-agent coordination occurs. Mailbox remains empty or undefined.

**MAS Scope:** Multi-agent communication is mandatory. Agents poll `.harness/mailbox.jsonl` (or equivalent queue) for peer messages without supervisor routing; P2P messages carry sender→recipient mappings; broadcast messages target agent_type or tag filters. Retry logic bounds retransmission to 3 attempts per message (tunable). Message delivery must complete within 1 polling cycle to prevent queue backlog.

**Transition Path:** SAS agent implementations should adopt message schema now (even if unused): `{sender, recipient, type, payload, threadId, timestamp}`. When scaling to MAS, the schema and delivery transport are already in place; only activate the mailbox polling loop and message-routing logic.

## L4: Concrete Actions & Tools

- **Action:** Implement a shared message queue or mailbox file that agents poll for directives.
  - **Tool:** Mailbox file format: `.harness/mailbox.jsonl` — JSON Lines, each line: `{sender: "agent-id", recipient: "agent-id"|"broadcast", type: "task"|"notification"|"status", threadId, payload, timestamp: ISO8601, ack_required: bool}`. Acceptance: file grows append-only; agents read only new lines since last position marker.
  - **Tool:** Mailbox poller script: `.agent/workflows/poll-mailbox.js` — reads new messages from `.harness/mailbox.jsonl` since last mark, filters by recipient, invokes handler for each message type. Acceptance: polling latency < 2 seconds; no messages lost or duplicated per cycle.

- **Action:** Define message schema (sender, receiver, type, payload, timestamp).
  - **Tool:** Message schema file: `.harness/message-schema.json` — JSON Schema with `$schema`, `title: "Inter-Agent Message"`, `properties: {sender, recipient, type, threadId, payload, timestamp, ack_required, retry_count, max_retries}`. Acceptance: all messages conform; validation happens on write via `.agent/workflows/validate-message.js`.
  - **Tool:** Acknowledgment mechanism: agents responding to `ack_required: true` write `.harness/mailbox-acks.jsonl` with `{msg_id, sender_id, recipient_id, ack_timestamp, status: "delivered"|"processed"|"failed"}`. Acceptance: all acks logged before agent release; supervisor can audit delivery tree.

- **Action:** Add P2P, broadcast, and idle notification communication strategies.
  - **Tool:** P2P routing: Messages with `recipient: "agent-{id}"` route directly. Acceptance: delivery within 1 polling cycle; if not delivered after 3 retries, logged to `.harness/message-failures.jsonl`.
  - **Tool:** Broadcast routing: Messages with `recipient: "broadcast"` filter agents by `target_agent_types` or `tags` field in payload; each matching agent receives a copy. Acceptance: fan-out completes in ≤ 1 cycle; fan-out tree logged to `.harness/broadcast-events.jsonl`.
  - **Tool:** Idle notification strategy: Agents emit "idle" messages (type: "status", payload: `{agent_id, state: "idle", task_id, timestamp}`) every 30s to mailbox. Supervisor queries idle pool to claim next task. Acceptance: idle detection latency < 60s; idle messages appear in `.harness/mailbox.jsonl` immediately after agent emit.

- **Action:** Bound message retry-logic.
  - **Tool:** Retry handler: `.agent/workflows/retry-message.js` — re-enqueues message if `retry_count < max_retries` (default 3). Resets `retry_count`, updates `timestamp`. Acceptance: retry count increments; original and retry messages both logged; no message sent > 4 times total (1 send + 3 retries).

## L4: Prevention

- **`P0-10` Prevent Unbounded Communication:** You must prevent agents from entering "ping-pong" loops where messages are sent back and forth without progress. Enforce this with message-count limits per task and mandatory structured objective-updates in every message.
- **`P0-10` Prevent Narrative Inter-Agent Messaging:** All inter-agent communication must follow a strict JSON schema to ensure automated routing and observability.

## L5: Gap Signals

- Agents coordinate only through shared files, with no structured messaging
- Agents enter infinite messaging loops without resolution
- Communication overhead exceeds reasoning budget
- Messages are lost or not acknowledged in MAS
- No audit trail of collective decision-making
