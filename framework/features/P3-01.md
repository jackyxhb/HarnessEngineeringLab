# P3-1. Scheduled Cleanups

> **Chain:** [EP-18](../principles/EP-18.md) → Entropy requires scheduled countering

## L2: Targeted Enhancement

Entropy never accumulates beyond one garbage collection cycle.

## L3: Design Decisions

Scheduled entropy audits (weekly or sprint-cadenced); dead code detection; orphan file identification; automated cleanup scripts; GC metrics.

## L4: Concrete Actions & Tools

- **Action:** Deploy entropy-countering agents on a regular schedule (weekly, sprint-cadenced) that detect and remove dead code, stale branches, orphan files, and documentation drift.
- **Action:** Track GC metrics (entropy removed per cycle, time since last cleanup).
- **Tool:** Cleanup scripts (dead code analyzers, branch pruners, orphan file detectors).
- **Tool:** `/reconcile` workflow for manual entropy audits.

## L4: Prevention

- **`P3-1, P3-3` Prevent Codebase Entropy:** You must prevent the natural accumulation of dead code, documentation drift, and circular dependencies generated by AI. Prevent this by deploying scheduled cleanup agents (garbage collection).

## L5: Gap Signals

- Dead code and stale branches accumulate without detection
- No regular cleanup schedule or automated entropy detection
- Orphan files persist indefinitely
- Entropy grows faster than it is removed

## L5: Improvement Policies

| Tier | Action | Dimensions |
| ------ | -------- | ------------ |
| 1 | Schedule weekly entropy audits with automated cleanup scripts | Maturity |
| 1 | Track entropy metrics (items removed per cycle, time since last GC) | Effectiveness |
| 2 | Build automated detection for dead code, stale branches, orphan files | Scalability |
| 3 | Implement predictive entropy detection — clean before it accumulates | Effectiveness |

## L5: Measurement

- Entropy never persists > 1 GC cycle
- Dead code ratio → 0
- Orphan file count → 0
