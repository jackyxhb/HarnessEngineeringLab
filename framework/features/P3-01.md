# P3-1. Scheduled Cleanups

> **Chain:** [EP-18](../principles/EP-18.md) → Entropy requires scheduled countering

## L2: Targeted Enhancement

Entropy never accumulates beyond one garbage collection cycle.

## L3: Design Decisions

Periodic removal of workspace junk; automated temporary file pruning; stale branch deletion; machine-readable cleanup logs; Machine-Readability First.

## L4: Concrete Actions & Tools

- **Action:** Deploy entropy-countering agents on a regular schedule (weekly, sprint-cadenced).
- **Action:** Track cleanup metrics (dead code lines removed, orphan files pruned, stale branches deleted per cycle, time since last cleanup).
- **Tool:** Cleanup scripts (dead code analyzers, branch pruners, orphan file detectors).
- **Tool:** `/reconcile` workflow for manual entropy audits.

## L4: Prevention

- **`P3-1, P3-3` Prevent Codebase Entropy:** You must prevent the natural accumulation of dead code, documentation drift, and orphan files. Prevent this with scheduled entropy-countering agents (garbage collection) that run on a fixed cadence.
- **`P3-1` Prevent Narrative Cleanup Reports:** Cleanup logs and entropy metrics must follow a machine-readable JSON format to enable automated trend analysis and regression detection.

## L5: Gap Signals

- Dead code and stale branches accumulate without detection
- No regular cleanup schedule or automated entropy detection
- Orphan files persist indefinitely
- Entropy grows faster than it is removed
