# P3-3. Pattern Auditing

> **Chain:** [EP-18](../principles/EP-18.md) → Entropy requires scheduled countering

## L2: Targeted Enhancement

Coding patterns converge to canonical forms; no circular dependencies persist.

## L3: Design Decisions

Pattern detection and normalization; canonical pattern registry; automated refactoring suggestions; circular dependency detection.

## L4: Concrete Actions & Tools

- **Action:** Audit codebase patterns regularly to ensure convergence toward canonical forms.
- **Action:** Detect and break circular dependencies.
- **Action:** Maintain a canonical pattern registry that defines approved patterns for common operations.
- **Tool:** Pattern analysis tools.
- **Tool:** Dependency graph analyzers (madge, eslint-plugin-import).
- **Tool:** `/reconcile` workflow for structural audits.

## L4: Prevention

- See P3-1 prevention: Codebase Entropy prevention applies jointly to P3-1 and P3-3.

## L5: Gap Signals

- Same problem solved N different ways across the codebase
- Circular dependencies growing unchecked
- No canonical patterns defined for common operations
- Pattern divergence increases with team/agent count

## L5: Improvement Policies

| Tier | Action | Dimensions |
| ------ | -------- | ------------ |
| 1 | Define canonical patterns for common operations and document in repo | Maturity |
| 1 | Add circular dependency detection to CI | Risk |
| 2 | Build automated pattern convergence detection and refactoring suggestions | Effectiveness |
| 2 | Maintain a living pattern registry reviewed quarterly | Scalability |
| 3 | Implement automated pattern migration (bot-generated PRs for convergence) | Scalability, Cost |

## L5: Measurement

- Pattern variants per operation → 1 (canonical)
- Circular dependency count → 0
- Pattern convergence rate > 90%

## Dependencies

**Requires:** P2-1 Automated Linters, P2-2 Dependency Enforcement
**Complements:** P3-1 Scheduled Cleanups
