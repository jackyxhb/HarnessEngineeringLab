# P3-3. Pattern Auditing

> **Chain:** [EP-18](../principles/EP-18.md) → Entropy requires scheduled countering

## L2: Targeted Enhancement

Systematic review of coding patterns; anti-pattern identification; architectural enforcement; machine-readable audit reports; Machine-Readability First.

## L3: Design Decisions

Pattern detection and normalization; canonical pattern registry; automated refactoring suggestions; circular dependency detection.

## L4: Concrete Actions & Tools

- **Action:** Audit codebase patterns regularly to ensure convergence toward canonical forms.
- **Action:** `P3-3` Prevent Pattern Drift: You must prevent agents from introducing diverse coding styles or anti-patterns that deviate from the project's established standards. Run periodic pattern audits and update `AGENTS.md` with new findings.
- **Action:** `P3-3` Prevent Narrative Pattern Audits: Pattern audit findings and anti-pattern definitions must follow a machine-readable JSON format to enable automated enforcement by linters.
- **Tool:** Pattern analysis tools.
- **Tool:** Dependency graph analyzers (madge, eslint-plugin-import).
- **Tool:** `/reconcile` workflow for structural audits.

## L4: Prevention

- See P3-1 prevention: Codebase Entropy prevention applies jointly to P3-1 and P3-3.

## L5: Gap Signals

- Anti-patterns propagate through the codebase unchecked
- No record of approved or forbidden coding patterns
- Inconsistent naming and structure make the codebase hard to audit
- Code reviews identify patterns too late in the development cycle
- Narrative Markdown tables in improvement policies (violating P1-1)
