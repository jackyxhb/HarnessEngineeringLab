# P0-8. Harness Versioning

> **Chain:** [EP-8](../principles/EP-08.md) → You cannot improve what you do not measure

## L2: Targeted Enhancement

Harness configurations are reproducible and comparable with data.

## L3: Design Decisions

VCS-tracked harness configuration; per-version agent performance metrics; A/B testing infrastructure; reusable template library of harness blueprints.

## L4: Concrete Actions & Tools

- **Action:** Version-control all harness configuration (prompts, tools, middleware).
- **Action:** Track agent performance metrics per harness version.
- **Action:** Build A/B testing pipeline to statistically compare harness variants.
- **Tool:** Version control (Git) for harness configs.
- **Tool:** Performance comparison dashboards.

## L4: Prevention

- **No specific prevention items.** Versioning absence is caught by gap signals.

## L5: Gap Signals

- No way to compare different harness configurations
- Changes to the harness are untested before deployment
- Cannot reproduce results from a previous harness version
- No data on which configurations produce better agent output

## L5: Improvement Policies

| Tier | Action | Dimensions |
| ------ | -------- | ------------ |
| 1 | Version-control all harness configuration (prompts, tools, middleware) | Maturity |
| 2 | Track agent performance metrics per harness version | Effectiveness |
| 3 | Build A/B testing pipeline to statistically compare harness variants | Human Role |
| 3 | Implement automated harness optimization (genetic/evolutionary search) | Scalability |

## L5: Measurement

- 100% of harness changes version-controlled
- A/B comparison data available per config change
- Regression detection time < 1 sprint

## Dependencies

**Requires:** P1-5 Observability (for performance data), P0-6 Rippable Middleware (for component-level versioning)
