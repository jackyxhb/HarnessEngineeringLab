# P2-4. Bounded Autonomy & Access Control

> **Chain:** [EP-17](../principles/EP-17.md) → Capabilities proportional to risk

## L2: Targeted Enhancement

Agent capabilities are proportional to task risk at all times.

## L3: Design Decisions

Defining tiered agent permissions; tool-access allow-lists; human-approval gates for high-risk actions; machine-readable permission manifests; Machine-Readability First.

## L4: Concrete Actions & Tools

- **Action:** Define tiered permission levels: read-only → file creation → code execution → deployment.
- **Action:** Implement tool access whitelists per task type — agents only receive tools appropriate for their current task.
- **Action:** Deploy guardrails for PII detection, secret scanning, and dangerous command prevention.
- **Action:** Require human approval gates for high-risk actions (production deployments, database migrations, external API calls with side effects).
- **Tool:** Permission configuration files.
- **Tool:** Guardrail middleware (secret scanners, PII detectors).
- **Tool:** Human-in-the-loop approval tools.

## L4: Prevention

- **`P2-4` Prevent Prompt Injections and Data Leakage:** You must prevent malicious inputs from manipulating agent instructions to steal API keys or expose PII.
- **`P2-4` Prevent Malicious Emergent Behaviors:** In autonomous swarms, you must prevent agents from executing logic bombs or deploying cryptographic evasion.
- **`P2-4` Prevent Unauthorized Privilege Escalation:** You must prevent agents from accessing or modifying resources beyond their assigned scope. Enforce this with tool-access white-lists and kernel-level sandboxing.
- **`P2-4` Prevent Narrative Permission Policies:** Agent permission levels and tool access manifests must be stored in a machine-readable JSON format to enable automated enforcement and audit.

## Enforcement Bindings

- **Registry:** `.harness/prevention-rules-registry.json`
- **Schema:** `framework/schemas/prevention-rules-registry.schema.json`
- **Rule:** `P2-4-prompt-injections-and-data-leakage` → status `declared-unmounted`; no checked-in prompt-injection or PII scanner is mounted yet.
- **Rule:** `P2-4-malicious-emergent-behaviors` → status `declared-unmounted`; MAS runtime guardrails are not mounted in this repository.
- **Rule:** `P2-4-unauthorized-privilege-escalation` → status `implemented`; `.harness/agent-permissions.json` is the canonical permission surface and is validated during audit.
- **Rule:** `P2-4-narrative-permission-policies` → status `implemented`; the permission policy surface is bound to `.harness/agent-permissions.json`.

## L5: Gap Signals

- Agent has unrestricted filesystem and execution access
- No guardrails for dangerous operations
- Agent can deploy to production without human approval
- No secret scanning or PII detection
- Agent capabilities do not scale with task risk

## Prevention Bindings

- **P2-4 Prevent Prompt Injections and Data Leakage:** Enforcement mechanism: `secret-scan.json` in CI blocks any commit containing keys/PII; prompt-injection filters implemented as system-prompt constraints (declared-unmounted).
- **P2-4 Prevent Malicious Emergent Behaviors:** Enforcement mechanism: Runtime guardrails monitoring agent tool-call patterns for anomalies (declared-unmounted).
- **P2-4 Prevent Unauthorized Privilege Escalation:** Enforcement mechanism: `.harness/agent-permissions.json` is the canonical permission surface; `scripts/audit.sh` validates that agent tool usage does not exceed assigned permission level.
- **P2-4 Prevent Narrative Permission Policies:** Enforcement mechanism: `he-lint.js` validates that permission levels are stored as JSON in `.harness/agent-permissions.json`.
