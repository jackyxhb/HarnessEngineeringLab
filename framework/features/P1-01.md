# P1-1. Repository as Truth

> **Chain:** [EP-11](../principles/EP-11.md) → If it's not in the repo, it doesn't exist

## L2: Targeted Enhancement

Agent context accuracy without human briefing.

## L3: Design Decisions

Failure Ledger (every rule traces to an incident); Forbidden Operations section; Tool Declaration; agent legibility optimization; expertise extraction (human corrections → harness artifacts).

## L4: Concrete Actions & Tools

- **Action:** Encode all project rules, architectural decisions, and style guides directly into the codebase at agent startup.
- **Action:** Cross-link design documents to ensure the model isn't blind to human knowledge.
- **Action:** Maintain a **Failure Ledger** — every rule in `AGENTS.md`/`CLAUDE.md` must trace to a concrete incident, failure, or constraint.
- **Action:** Include a **Forbidden Operations** section explicitly listing what agents must never do, with consequences stated inline.
- **Action:** Maintain a **Tool Declaration** section listing every available tool and script — undeclared tools do not exist to agents.
- **Action:** Optimize the codebase for **agent legibility**: prefer stable, well-documented frameworks; maintain clear module boundaries; minimize metaprogramming.
- **Action:** Implement **expertise extraction**: when a human corrects an agent mistake, the correction must be encoded as a new harness artifact — not just applied as a code fix.
- **Tool:** IDE-agnostic `AGENTS.md` as canonical rule surface, with IDE shims for discovery.
- **Tool:** Structured failure-ledger entry format (e.g., `rule / context / fix` triples).

## L4: Prevention

- **`P1-1` Prevent Human-Only Documentation:** You must prevent project rules, APIs, and architectural decisions from living only in human heads, Slack threads, or private Google Docs.
- **`P1-1` Prevent Human-Only Documentation Format:** You must prevent documentation structured exclusively for human consumption (narrative prose, unstructured paragraphs). All documentation must be simultaneously machine-parseable.
- **`P1-1, P1-7` Prevent Inconsistent Shared Context:** In a MAS, you must prevent agents from operating on conflicting or outdated information.

## L5: Gap Signals

- Project rules live in Slack, Google Docs, or human memory
- Agent hallucinates because it lacks access to architectural decisions
- Onboarding a new agent requires extensive human briefing
- `CLAUDE.md` or `AGENTS.md` is absent or stale

## L5: Improvement Policies

| Tier | Action | Dimensions |
| ------ | -------- | ------------ |
| 1 | Create and maintain `CLAUDE.md` / `AGENTS.md` with project conventions | Maturity |
| 1 | Migrate all architectural decisions from external tools into the repo | Risk, Effectiveness |
| 2 | Add linter validation that context files are present and non-empty | Risk |
| 2 | Cross-link design docs to code modules for agent discoverability | Effectiveness |
| 2 | Score codebase Agent Legibility and address low-scoring criteria | Effectiveness, Cost |
| 2 | Implement expertise extraction: every human correction → new harness artifact | Human Role, Effectiveness |
| 3 | Automate staleness detection — alert when docs diverge from code | Scalability |

## L5: Measurement

- New agent onboarding requires 0 human conversations
- Hallucination rate on project conventions → 0
- Agent Legibility Score ≥ 3.0
