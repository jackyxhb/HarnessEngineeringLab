# Harness Engineering (HE) Core Philosophy

> _Canonical framework: `framework/Core Features for SAS.md` | MAS extension: `framework/Core Features for MAS.md`_

Harness Engineering is an AI-first development methodology where humans design environments and agents write the code. It represents an extreme application of "shift-left" where software discipline moves completely from the code level into the repository's scaffolding.

## 1. Humans Steer, Agents Execute

Engineers stop writing code directly. Their primary job changes to designing the environment, specifying intent, validating outcomes, and building automated feedback loops. Human time is the scarcest resource; it is protected ruthlessly by pushing execution and review workloads continuously to the agents.

## 2. Safety and Architecture by Design

Architectural decisions cannot rely on human memory, tribal knowledge, or convention. They must be explicitly encoded and mechanically enforceable via linters, structural tests, and CI/CD pipelines. When an agent fails, you do not fix the code yourself—you fix the environment by adding a mechanical guardrail (like a structural test or targeted linter) so the agent learns to self-correct in the future.

## 3. The 3-Pillar Framework

The methodology relies on a structured 3-Pillar + Foundation framework to channel raw agent intelligence productively:

- **Foundation (Execute):** The robust execution engine, providing isolated sandboxes, version control, self-verification loops, and rippable middleware.
- **Pillar 1: Context Engineering (Inform):** Memory and context management, treating the repository as the sole source of truth and compounding context anchoring to prevent strategic drift.
- **Pillar 2: Architectural Constraints (Constrain):** Mechanical enforcement of rigid boundaries, rejecting bad code through formatters, strict dependency chains, and AI-assisted auditors.
- **Pillar 3: Entropy Management (Maintain):** Background janitorial processes, running scheduled cleanups and documentation consolidation loops to combat the high-volume slop generated by LLMs.

## 4. Legibility over Optimization

Agents model well-documented and widely-used technologies much more accurately than niche, opaque abstractions. Favor established, boring technologies and ensure everything the agent needs to know is directly legible within the repository format. If an agent cannot read it in the repository, it effectively does not exist.
