## L2: Targeted Enhancement

Agent coordination overhead stays sublinear relative to team size.

## L3: Design Decisions

Topology selection (Supervisor, Hierarchical, P2P, Blackboard, Swarm); automated router logic; tiered task priority queues; worker-agent pool management; shared blackboards for collective intent; context-preserving handoffs; generator/evaluator role separation; 4–6 specialized starting roles; Machine-Readability First.

## Scope: SAS vs MAS

**SAS Scope:** Single-agent orchestration logic remains bounded; no topology switching required. Agents use sequential task processing with implicit priority (FIFO). Context handoffs occur within a single agent's memory window, and no distributed state synchronization is needed. The constraint is internal execution order only (no inter-agent coordination overhead).

**MAS Scope:** Multi-agent orchestration distributes tasks across agent pool; topology selection and dynamic switching become critical to minimize coordination cost. Shared blackboards and message routing ensure agents do not collide on task claims. Handoff protocols must preserve full context across agent boundaries to prevent state loss.

**Transition Path:** SAS implementations lay groundwork with clean task-routing interfaces and JSON-standard task schemas. When moving to MAS, these interfaces scale directly: swap single-threaded task loop for multi-agent dispatcher; upgrade shared files to message queues; activate topology selection logic. No architectural refactor required if SAS foundation is properly abstracted.

## L4: Concrete Actions & Tools

- **Action:** Implement basic supervisor pattern (central orchestrator → workers) — *MAS Phase 2*
  - **Tool:** Subagent spawning script: `.agent/workflows/spawn-subagent.js` — accepts `{agent_name, task_id, context, timeout_ms}`, returns `{agent_id, status_endpoint}`.
  - **Acceptance Criteria:** Spawned agents appear in `.harness/agent-registry.json` within 500ms; zero task loss during spawn.

- **Action:** Add topology selection based on task type (parallel vs. sequential) — *MAS Phase 2*
  - **Tool:** Task router script: `.agent/workflows/route-task.js` — reads `.agent/workflows/topology-config.json` and task metadata, routes to appropriate agent pool.
  - **Tool:** Priority queue manager: `.harness/task-queue.json` — maintains ordered list with priority levels 0-5.
  - **Acceptance Criteria:** Routing decision logged to `.harness/router-events.jsonl` per schema; priority order stable; zero task skips.

- **Action:** Build context-preserving handoff protocols between agents — *MAS Phase 2*
  - **Tool:** Handoff protocol: task file format `.harness/task-{id}.json` with context and state fields.
  - **Tool:** Context validation script: `npm run validate-handoff -- <task_id>` — verifies required_state fields before agent claims task.
  - **Acceptance Criteria:** No context fields omitted; `prior_findings` ≥ 50 chars per handoff; incomplete context escalates to supervisor.

- **Action:** Support dynamic topology switching (supervisor ↔ peer-to-peer ↔ swarm) — *MAS Phase 2*
  - **Tool:** Topology switch handler: `.agent/workflows/switch-topology.js` — drains in-flight tasks, reconfigures queue routing, logs switch event.
  - **Tool:** Topology health monitor: `npm run observe` consumes `.harness/orchestration-metrics.json` (schema: `.harness/orchestration-metrics.schema.json`).
  - **Acceptance Criteria:** Zero task loss during switch; all agents acknowledge new topology within 1 cycle; supervisor latency ≤ 5000ms.

## L4: Prevention

- **`P0-5` Prevent Quadratic Coordination Overhead:** You must prevent the exponential growth of communication paths between agents. Over-communicating can degrade performance by 39% to 70% on sequential reasoning tasks. Prevent this by using appropriate routing topologies and limiting team sizes.
  - **Status:** Declared-unmounted (MAS Phase 2).
  - **Reason:** SAS single-agent execution does not require inter-agent communication. Topology selection and coordination-cost monitoring will be mounted once MAS router infrastructure is active.
  - **Registry Status:** `declared-unmounted`.

- **`P0-5` Prevent Supervisor Bottlenecks:** In hierarchical or supervisor patterns, you must prevent the central coordinating agent from becoming a single point of failure that stalls the entire workflow when request volumes spike.
  - **Status:** Declared-unmounted (MAS Phase 2).
  - **Reason:** SAS has no orchestration supervisor. MAS will implement supervisor queue monitoring with fallback to peer-to-peer topology if latency exceeds thresholds.
  - **Registry Status:** `declared-unmounted`.

- **`P0-5` Prevent Coordination Failure:** You must prevent agents from being assigned redundant work or tasks with unmet dependencies. Enforce this by implementing a centralized or distributed task router that respects task-wait states and dependency chains.
  - **Status:** Declared-unmounted (MAS Phase 2).
  - **Reason:** SAS uses sequential FIFO task processing with no distributed assignment logic. MAS will implement distributed task routing with deduplication and dependency resolution.
  - **Registry Status:** `declared-unmounted`.

- **`P0-5` Prevent Non-Parseable Orchestration Plans:** Orchestration and routing logs must be JSON-standardized to enable high-speed automated auditing of coordination overhead.
  - **Status:** Declared-unmounted (MAS Phase 2).
  - **Tool (Future):** `.harness/orchestration-metrics.json` will record supervisor latency, queue depth, and topology active state (schema: `.harness/orchestration-metrics.schema.json`).
  - **Tool (Future):** `.harness/router-events.jsonl` will log all routing decisions with structured fields (schema: `.harness/router-events.schema.json`).
  - **Acceptance Criteria (Future):** All orchestration logs conform to JSON schemas defined in registry.
  - **Registry Status:** `declared-unmounted`.

## L5: Gap Signals

- Only one agent can work at a time
- No automated router logic or task-priority queues
- Worker-agent pool management is absent or cannot scale with demand
- Shared blackboards or equivalent coordination state are absent
- Subagent spawning is manual or impossible
- Task handoffs lose context
