# P0-1. Bash Sandboxes

> **Chain:** [EP-1](../principles/EP-01.md) → Isolation prevents contamination

## L2: Targeted Enhancement

Zero cross-contamination between agent execution environments.

## L3: Design Decisions

Isolated containers/VMs per agent session; pre-installed language runtimes, test runners, CLI tools; visual monitoring of sandbox state (tmux, split-pane terminals); Ephemeral State Management; Determinism.

## L4: Concrete Actions & Tools

- **Action:** Provision safe, scalable, isolated execution environments for every agent session.
- **Tool:** General-purpose bash execution tools.
- **Tool:** Sandboxes pre-installed with language runtimes (Node.js, Python, Go), test runners (Jest, pytest), and CLI tools (git, npm, docker).
- **Tool:** Visual split-pane terminals (tmux) for real-time monitoring of sandbox state.

## L4: Prevention

- **`P0-1` Prevent Persistent Local State:** Every sandbox must be ephemeral and reset to a clean image after each session.
- **`P0-1` Prevent Unmonitored Sandbox State:** Side-effects must be visually or log-detectable (using tmux or split-pane terminals).
- **`P0-1` Prevent Network Bypass:** Sandboxes must have controlled, audited network egress to ensure no non-deterministic data leakage.

## L5: Gap Signals

- Agents execute code on the developer's local machine
- No isolation between agent sessions
- Agent cannot install packages or run arbitrary commands
- Failures in one agent's execution corrupt another's environment
- **Environment persistence across agent sessions (violating P0-1)**
- **Undetected side-effects in unmonitored sandboxes**
