# P1-6. Web Search & MCP Integration

> **Chain:** [EP-12](../principles/EP-12.md) → Finite attention demands active management

## L2: Targeted Enhancement

Agent answers reflect current state of the world.

## L3: Design Decisions

Web search tool integration; MCP server connections for domain-specific context; caching layer; relevance filtering; machine-readable MCP capability manifests; Machine-Readability First.

## L4: Concrete Actions & Tools

- **Action:** Give agents access to real-time knowledge and current data beyond their training cutoff.
  - **Tool:** Web search API integration: Anthropic WebSearch tool (available via `mcp__multi-ai-collab__*` endpoints) or integration with third-party search (Google Custom Search API, Brave Search API, DuckDuckGo API).
  - **Tool:** API endpoints: WebSearch via `https://api.search.anthropic.com/v1/search` (or provider-specific endpoint); MCP servers via MCP protocol on `localhost:<port>` or remote URLs.
  - **Acceptance Criteria:** Agent can invoke web search within 2 seconds; search results returned within 5 seconds; agent includes source URLs in responses.

- **Action:** Connect MCP servers for domain-specific external context.
  - **Tool:** MCP server manifest: `.harness/mcp-capabilities.json` lists all available MCP servers with: `server_id`, `protocol`, `endpoint`, `description`, `auth_required`, `rate_limit`, `capabilities`.
  - **Tool:** MCP discovery: agent reads `.harness/mcp-capabilities.json` at startup; for each MCP server, agent queries capabilities and adds tools to available set.
  - **Acceptance Criteria:** Agent auto-discovers all MCP servers listed in manifest; agent can invoke MCP tools without hardcoding endpoints.

- **Action:** Implement rate limiting and caching to reduce redundant external lookups.
  - **Tool:** Rate limit enforcement: per AGENTS.md, observe provider rate limits (e.g., Anthropic WebSearch: 100 req/min for free tier, 1000 req/min for paid). Store limits in `.harness/mcp-capabilities.json` as `rate_limit: { "requests": 100, "window_seconds": 60 }`.
  - **Tool:** Cache layer: `.harness/search-cache.json` (key=query, value=result+timestamp) with TTL: web search results cached for 24 hours, MCP results cached for 12 hours (configurable per server).
  - **Tool:** Cache hit logic: before calling external API, check `.harness/search-cache.json`; if query exists and fresh (within TTL), return cached result; otherwise call API and update cache.
  - **Acceptance Criteria:** Cache hit rate > 60% for repeated queries; rate limit violations = 0 (escalate to human if limit exceeded).

- **Action:** Build relevance filtering so agent decides when external search adds value.
  - **Tool:** Relevance decision logic: agent evaluates task context and decides: (1) Is this a time-sensitive query (news, prices, versions, recent changes)? → call web search. (2) Is this a standard question (definitions, algorithms, concepts already in training)? → answer in-context. (3) Is this domain-specific (API docs, internal tools)? → query MCP server.
  - **Tool:** Logging rule: log each external query decision to `.harness/knowledge-lookup.jsonl`: timestamp, query, decision_reason, source (web|mcp|in-context), result_quality_score.
  - **Acceptance Criteria:** Agent avoids redundant external lookups (e.g., searching for "what is Python" when it's in training); agent prefers cached results when available; knowledge-lookup log shows > 70% of queries were correctly routed.

## L4: Prevention

- **`P1-6` Prevent Knowledge Silos:** You must prevent agents from being limited to their internal training data for fast-moving topics. Mandate web-search or MCP-knowledge retrieval for external research tasks.
- **`P1-6` Prevent Narrative MCP Server Manifests:** MCP server configurations and capability definitions must follow a machine-readable JSON format to ensure automated tool-binding.

## L5: Gap Signals

- Agent produces outdated answers for rapidly evolving domains
- No access to external APIs, documentation, or real-time data
- Agent cannot look up library versions or API changes
- Agent hallucinates information that is available via search
- MCP integrations are brittle and require manual configuration
- Knowledge retrieval overhead exceeds reasoning benefits
- No audit trail of external data used in decision making
