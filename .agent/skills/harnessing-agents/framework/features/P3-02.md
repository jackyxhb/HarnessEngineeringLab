# P3-2. Documentation Sync

> **Chain:** [EP-11](../principles/EP-11.md) → If it's not in the repo, it doesn't exist

## L2: Targeted Enhancement

Documentation always matches the current state of the code.

## L3: Design Decisions

Ensuring alignment between code and docs; automated doc-generation; CI checks for doc staleness; machine-readable documentation maps; Machine-Readability First.

## Scope: SAS vs MAS

**SAS Scope:** Single-agent documentation sync is straightforward — all docs are co-located in the repository alongside code. Scheduled sync (e.g., nightly doc-generation from code) is sufficient; no event-driven sync logic required. Doc staleness detection runs on fixed intervals (pre-commit or CI).

**MAS Scope:** Multi-agent environments introduce distributed code and documentation across multiple repositories or microservices. Event-driven sync becomes critical: when one agent modifies a module's documentation in its local repo, an event fires to trigger downstream doc-generation in dependent repos. Sync must happen before dependent agents consume the module. Documentation maps must track cross-service dependencies.

**Transition Path:** SAS implementations should build doc-generation automation and machine-readable doc maps now (even if single-repo). When scaling to MAS, upgrade scheduled sync to event-triggered sync using the same doc-generation tools and map structure. No re-architecture required if doc pipeline is decoupled from the repository topology.

## L4: Concrete Actions & Tools

- **Action:** Ensure documentation is updated in the same commit/PR as the code it describes.
  - **Tool:** Commit hook: `.git/hooks/pre-commit` (or `scripts/harness/pre-commit.sh`) — checks for files matching pattern `(code|src|lib|\.agent)/` and verifies corresponding docs/ entries are staged. Acceptance: hook fails if code changed but no doc changes staged in same commit (user can override with `--no-verify` if docs truly unchanged).
  - **Tool:** PR check: CI workflow `.github/workflows/doc-sync-check.yml` — compares code diff against doc diff; reports if code-only or doc-only changes detected. Acceptance: fails PR if code changes lack corresponding doc updates; message directs user to which docs need updating.

- **Action:** Implement automated staleness detection — alert when docs diverge from code.
  - **Tool:** Doc-staleness scanner: `npm run lint:doc-staleness -- [<code-dir>] [<doc-dir>]` — reads machine-readable doc map (see next tool), compares file modification times: if code_mtime > doc_mtime, marks doc as stale. Acceptance: reports which docs are stale and how many days behind code; exits non-zero if staleness > 30 days.
  - **Tool:** Doc map file format: `.harness/doc-map.json` — structure: `{mappings: [{code_file: "path/to/code.js", doc_file: "path/to/doc.md", last_sync_timestamp, sync_type: "scheduled"|"event-driven"}]}`. Acceptance: map is updated every time a code-doc pair is synced (via manual edit or automation); validators confirm all code_file paths exist.
  - **Tool:** Automated staleness alerter: `npm run observe` updates `.harness/doc-staleness-report.json` with `{stale_docs: [{doc_file, code_file, days_behind}], check_timestamp}`. Acceptance: report generated on every audit run; if any doc > 30 days stale, `npm run audit` exits WARN (not FAIL, but visible in dashboard).

- **Action:** Co-locate documentation with the code modules it describes whenever possible.
  - **Tool:** Co-location validator: `npm run lint:doc-colocation -- <module-dir>` — checks if each `.js` or `.py` module has adjacent `.md` file or documented cross-reference. Acceptance: for each code file, validator confirms either (a) `.md` sibling exists, or (b) `framework/` feature doc references it explicitly, or (c) status file `.harness/doc-exemptions.json` lists it as exempt with reason.
  - **Tool:** Doc-cross-reference format: in code files, include comment block at top: `// DOC: ../docs/module-name.md` or `// DOC: framework/features/P0-01.md#section`. Acceptance: linter scans all code files for DOC markers; confirms referenced docs exist; builds cross-reference index.

- **Action:** Implement doc-generation from code analysis.
  - **Tool:** Doc-generator script: `.agent/workflows/generate-docs.js` — reads code file, extracts structured comments (e.g., JSDoc, Python docstrings), generates `.md` file with signature, parameters, return values, examples. Acceptance: generated docs include at least function signatures and parameter descriptions; can be optionally augmented by humans without clobbering on re-generation.
  - **Tool:** Doc-generation trigger: In MAS mode, GitHub workflow or event-driven trigger (e.g., code push) calls `npm run generate-docs -- <changed-file>` and commits result. Acceptance: generated docs appear in the same PR/commit as code changes; no human manual doc-writing required for API signatures.

- **Action:** Enable CI staleness checks.
  - **Tool:** CI staleness gate: `.github/workflows/doc-freshness.yml` — runs `npm run lint:doc-staleness` on every PR; blocks merge if any doc > 7 days behind main. Acceptance: CI job exits 0 only if all mapped docs are within staleness threshold; failure message lists stale files and directs to remediation.
  - **Tool:** Measurement binding: In MAS mode, `.harness/doc-sync-metrics.json` tracks `{total_docs, stale_count, avg_staleness_days, sync_events_count}` and updates every doc-generation run. Acceptance: `npm run observe` includes doc-sync data in dashboard metrics.

## L4: Prevention

- **`P3-2, P3-4` Prevent Documentation Disconnects (Missing Consolidation):** You must prevent core system counts and architectural records from drifting out of sync. Enforce with CI checks for doc staleness and machine-readable documentation maps co-located with the code they describe.
- **`P3-2` Prevent Narrative Documentation Maps:** Documentation-to-code cross-reference maps must be JSON-standardized to allow CI enforcement of coverage and freshness.

## L5: Gap Signals

- Documentation describes features that no longer exist
- Code changes land without corresponding doc updates
- README is perpetually outdated
- Developer documentation contradicts actual code behavior
