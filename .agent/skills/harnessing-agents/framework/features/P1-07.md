# P1-7. Planning, Task Lists & Blackboards

> **Chain:** [EP-2](../principles/EP-02.md) → State must outlive the session

## L2: Targeted Enhancement

Complex tasks survive context resets and are decomposed before execution.

## L3: Design Decisions

Filesystem-based plan files; plan reminder injection; structured format (goal, scope, status, steps, constraints, checkpoints); shared blackboards for MAS; completed plans archived inline.

## L4: Concrete Actions & Tools

- **Action:** Maintain a shared task list where agents can autonomously view statuses, claim unassigned work, and build upon partial solutions.
- **Action:** Store plan files and inject reminders so agents can decompose goals and stay on track.
- **Action:** Formal planning phase for multi-step tasks; explicit plan artifacts (`PLANS.md`); version-controlled task lists; machine-parseable plan structures; Machine-Readability First.
- **Action:** Front-load enough durable context in every plan entry that an agent can resume the task from the plan file alone after a context reset.
- **Action:** Archive completed plan entries inline rather than deleting them, preserving a traceable record.
- **Tool:** Centralized knowledge spaces (Blackboards).
- **Tool:** The filesystem (for storing shared plan files, e.g., `PLANS.md` in the project root).

## L4: Prevention

- **`P1-7` Prevent Planless Execution:** You must prevent agents from starting complex tasks (>3 steps) without a documented plan. Plans must be version-controlled and updated at each phase.
- **`P1-7` Prevent Narrative Task Plans:** Project plans and task boards must be stored in a machine-readable JSON/YAML format to enable automated coordination and status tracking.

## L5: Gap Signals

- Agent approaches complex tasks without decomposing them
- No persistent plan that survives context window resets
- Agent repeats work it already completed in a previous step
- No shared task board for MAS coordination
- Task handoffs fail due to implicit plan assumptions
