# P0-4. Ralph Loops

> **Chain:** [EP-4](../principles/EP-04.md) → Committed tasks must be completed

## L2: Targeted Enhancement

100% task completion rate regardless of context window exhaustion.

## L3: Design Decisions

Exit interception hooks; prompt reinjection with state summary; loop budgets to prevent infinite retries; integration with Planning for cross-window persistence.

## L4: Concrete Actions & Tools

- **Action:** Implement exit interception hooks that detect premature completion.
  - **Tool:** `node scripts/exit-interceptor.js` — Runs after task completion to detect incomplete steps against `.harness/task-state.json`.
  - **Tool:** `.harness/task-state.json` schema-driven state file per AGENTS.md; must conform to `.harness/task-state.schema.json`.
  - **Acceptance Criteria:** Exit interceptor detects any task with status != `completed` within 1 second of exit; triggers reinjection if steps remain unfinished.

- **Action:** Build prompt reinjection with state summary into fresh context windows.
  - **Tool:** State persistence format: `.harness/task-state.json` with fields: `task_id`, `status`, `steps` (array of completed/pending steps), `last_checkpoint`, `reinjection_count`, `heartbeat_timestamp`.
  - **Tool:** Reinjection script reads `.harness/task-state.json`, compacts state summary to < 500 tokens, and prepends to fresh prompt: "Resume task [task_id]. Completed: [steps]. Pending: [steps]. Context: [checkpoint_data]."
  - **Acceptance Criteria:** Reinjected prompt includes task context, completed steps, and pending work; agent resumes from exact failure point without repeating work.

- **Action:** Add loop budgets (max reinjections) to prevent infinite retries.
  - **Tool:** Loop budget enforcement via `AGENTS.md` rule: "Maximum 3 reinjections per task to prevent infinite retries. Escalate to human review after 2 failed reinjections."
  - **Tool:** Loop detection: `.harness/task-state.json` field `reinjection_count` increments on each reinjection; when it reaches 3, trigger escalation to `.harness/escalation-events.jsonl`.
  - **Acceptance Criteria:** Task reinjections never exceed 3; after 2 consecutive failures, escalation event is created with diagnostic details (what was attempted, why it failed, proposed alternative).

## L4: Prevention

- **`P0-4` Prevent Premature Exits:** You must prevent models from stopping early or losing coherence over long horizons. Enforce this with exit interception hooks, per-step checkpointing, and automatic state reinjection after context resets.
- **`P0-4` Prevent Narrative Task State:** Task state snapshots and reinjection payloads must follow a machine-readable JSON schema to enable deterministic resumption and audit across context windows.

## L5: Gap Signals

- Agent stops mid-task and declares "done" prematurely
- Long-horizon tasks consistently produce incomplete results
- Agent loses task context after restart
- Monolithic Tasks fail due to resource exhaustion or timeouts
- No record of current execution state for long-running processes
- Incomplete tasks cannot be resumed from the point of failure
