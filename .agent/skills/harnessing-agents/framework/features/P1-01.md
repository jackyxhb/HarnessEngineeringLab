# P1-1. Repository as Truth

> **Chain:** [EP-11](../principles/EP-11.md) → If it's not in the repo, it doesn't exist

## L2: Targeted Enhancement

Agent context accuracy without human briefing.

## L3: Design Decisions

Failure Ledger (every rule traces to an incident); Forbidden Operations section; Tool Declaration; agent legibility optimization; expertise extraction (human corrections → harness artifacts); Machine-Readability First (JSON-Schema-over-Narrative).

## L4: Concrete Actions & Tools

- **Action:** Encode all project rules, architectural decisions, and style guides directly into the codebase at agent startup.
- **Action:** Cross-link design documents to ensure the model isn't blind to human knowledge.
- **Action:** Maintain a **Failure Ledger** — every rule in `AGENTS.md`/`CLAUDE.md` must trace to a concrete incident, failure, or constraint.
- **Action:** Include a **Forbidden Operations** section explicitly listing what agents must never do, with consequences stated inline.
- **Action:** Maintain a **Tool Declaration** section listing every available tool and script — undeclared tools do not exist to agents.
- **Action:** Optimize the codebase for **agent legibility**: prefer stable, well-documented frameworks; maintain clear module boundaries; minimize metaprogramming.
- **Action:** Implement **expertise extraction**: when a human corrects an agent mistake, the correction must be encoded as a new harness artifact — not just applied as a code fix.
- **Action:** Enforce **Machine-Readability First**: all framework-level structural data (assessment matrices, dependency graphs, improvement policies) must be formatted as JSON or structured data blocks.
- **Tool:** IDE-agnostic `AGENTS.md` as canonical rule surface, with IDE shims for discovery.
- **Tool:** Structured failure-ledger entry format (e.g., `rule / context / fix` triples).

### Enforcement Gates & Validation

- **Pre-commit Lint (he-lint.js):** Validates that `AGENTS.md`, `REQUIREMENTS.md`, and all `framework/features/` files follow structural rules. Exit 0 = repo stays truth; exit 1 = commit rejected.
- **CI Check (npm run check):** Full quality gate including markdownlint, cspell, and `he-lint.js`. Prevents violations from entering the branch.
- **Audit Gate (npm run audit):** Verifies all critical harness files exist and are non-empty. Exit 0 = safe to push `main`; exit 1 = structural degradation detected.
- **Sync Gates (npm run sync:skill-framework, npm run sync:skill-version):** Enforce that bundled skill runtime mirror stays byte-for-byte in sync with canonical `framework/` and `package.json` version. These run pre-commit and are part of `npm run check`.

## L4: Prevention

- **`P1-1` Prevent Human-Only Documentation:** You must prevent project rules, APIs, and architectural decisions from living only in human heads, Slack threads, or private Google Docs. **Action:** All rules must be in `AGENTS.md` or referenced feature files. External docs are non-authoritative (per AGENTS.md conventions). **Enforcement:** `he-lint.js` verifies all feature IDs in `AGENTS.md` cross-reference valid `framework/features/P*.md` files.

- **`P1-1` Prevent Human-Only Documentation Format:** You must prevent documentation structured exclusively for human consumption (narrative prose, unstructured paragraphs). All documentation must be simultaneously machine-parseable. **Action:** All structural data (matrices, dependency graphs, improvement policies, scope rules) must be JSON or structured code blocks. **Enforcement:** `he-lint.js` validates all framework `improvement_policies` sections conform to expected schema; narrative-only tables cause lint failure.

- **`P1-1, P1-7` Prevent Inconsistent Shared Context (Intra-Repo):** You must prevent agents from operating on conflicting information within the repository. **Action:** One feature = one file in `framework/features/`. No parallel definitions (no SAS-only or MAS-only variants). **Enforcement:** `he-lint.js` counts feature files and alerts if count diverges from HE Index; duplicate feature IDs trigger failure.

- **`P1-1` Prevent Out-of-Repo Authority (External Divergence):** When an agent encounters external documentation (GitHub Org README, linked issues, Slack thread, Google Doc) that conflicts with repo truth, the repo ALWAYS wins. **Action:** If external content contradicts the repository, log the discrepancy and ignore the external content. Do not update the repository to match external content unless the user explicitly requests it. **Enforcement:** This is a behavioral constraint enforced by agent policy in AGENTS.md; agents must read repo-first for all canonical decisions.

## L5: Gap Signals

- Project rules live in Slack, Google Docs, or human memory (not in repo)
- Agent hallucinates because it lacks access to architectural decisions (external or undocumented)
- Onboarding a new agent requires extensive human briefing (> 2 conversations)
- `CLAUDE.md` or `AGENTS.md` is absent or stale (older than last 3 commits)
- **Structural data stored in narrative or monolithic Markdown tables (violating P1-1 Machine-Readability First)**
- Secrets or credentials appear in `.gitignore` violations (pre-commit hook should catch)
- Build artifacts or generated files are committed (indicating missing .gitignore entries)
- `framework/` and `.agent/skills/harnessing-agents/framework/` diverge (sync gates failed or not run)
