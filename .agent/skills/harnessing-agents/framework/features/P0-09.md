# P0-9. Smart Command Wrappers

> **Chain:** [EP-9](../principles/EP-09.md) → Standard operations reduce variance

## L2: Targeted Enhancement

Zero variance in common CLI workflow execution. All multi-step operations (commit, release, audit) executed through canonical workflow definitions and npm scripts, never raw commands. All command output machine-readable (JSON for agent consumption, Markdown for human review). Latency guarantees at each cost tier enforced by pre-commit and pre-push gates.

## L3: Design Decisions

### Three Core Workflows

Intelligent intent-based workflows replace raw CLI chains. Each workflow is a canonical Markdown definition in `.agent/workflows/` that describes steps in human terms and maps to npm script wrappers and git commands.

1. **`/ccp` — Comment, Commit, Push**
   - Intent: Finalize incremental work and push to tracking branch
   - Steps: Review changes → Stage → Generate commit message → Commit → Push
   - Output: Git commit + remote push
   - Enforcement: `npm run smoke` (pre-commit)
   - Latency target: < 2s baseline + git push network time

2. **`/ccpr` — Comment, Commit, Push, GitHub Release**
   - Intent: Finalize work and create a GitHub release with versioned artifact
   - Steps: Commit (via `/ccp`) → Compute release tag from `package.json` → Create git tag → Generate release notes from `RELEASES.md` + git log → Create GitHub release via `gh` command
   - Output: Git commit + git tag + GitHub Release artifact (API)
   - Enforcement: `npm run check` (pre-push)
   - Latency target: < 30s (excluding GitHub API latency, which is acceptable)

3. **`/reconcile` — Workspace Entropy Audit**
   - Intent: Systematically audit entire workspace for entropy, deduplicate content, standardize terminology, and bridge concept gaps
   - Steps: Inventory active surfaces → Analyze against canonical definitions → Produce findings report → Execute approved fixes → Commit
   - Output: Markdown findings report + git commit with applied fixes
   - Enforcement: `npm run audit` (on-demand, pre-release)
   - Latency target: < 60s (complexity scales with repo size)

### Tool Stack

- **Workflow Definitions:** Markdown (`.agent/workflows/ccp.md`, `ccpr.md`, `reconcile.md`) — human-readable, agent-executable
- **npm Scripts:** `npm run smoke` (he-lint.js only), `npm run check` (markdownlint + cspell + he-lint.js), `npm run audit` (harness structural audit)
- **Git Commands:** Wrapped in Bash scripts or directly in npm scripts
- **GitHub CLI (`gh`):** For release creation (step 11 in `/ccpr`)
- **Smart Wrappers:** npm scripts serve as intent-based CLI proxies, replacing raw `git commit`, `npm run`, `git push`, etc.

## L4: Concrete Actions & Tools

### Workflow 1: `/ccp` (Comment, Commit, Push)

**Canonical definition:** `.agent/workflows/ccp.md`

**Step-by-step execution:**

1. Review changes

   ```bash
   git status
   git diff --stat
   ```

   Output: Human review of what will be committed.

2. Stage all changes

   ```bash
   git add -A
   ```

   Output: Staged changes ready for commit.

3. Generate commit message
   - Parse `git diff --stat` output
   - Infer intent: feature, fix, docs, refactor
   - Generate conventional-commit format: `<type>(<scope>): <summary>`
   - Example: `feat(P0-9): enhance smart command wrappers with output standards`
   - Output: Formatted commit message string

4. Commit

   ```bash
   git commit -m "<generated-message>"
   ```

   Output: Git commit object with message.

5. Push to remote

   ```bash
   git push
   ```

   If upstream not set, fallback:

   ```bash
   git push -u origin <current-branch>
   ```

   Output: Changes synced to remote tracking branch.

**Error handling:**
- If no changes staged: Stop and inform user ("No changes to commit")
- If push fails: Suggest upstream setup or ask user for guidance

**Latency enforcement:** Pre-commit hook runs `npm run smoke` (he-lint.js only, < 2s) before accepting the commit message. Failure blocks commit.

### Workflow 2: `/ccpr` (Comment, Commit, Push, GitHub Release)

**Canonical definition:** `.agent/workflows/ccpr.md`

**Step-by-step execution:**

1–5. Run `/ccp` workflow (commit and push all changes)
   Output: Remote branch updated.

1. Compute canonical release tag

   ```bash
   node -e "console.log('v' + require('./package.json').version)"
   ```

   Validate user-supplied tag against computed tag. If mismatch, ask whether to use canonical tag or bump version.
   Output: Release tag string (e.g., `v4.1.1`)

2. Create annotated git tag

   ```bash
   git tag -a v4.1.1 -m "Release v4.1.1"
   ```

   Output: Local git tag created.

3. Push tag to remote

   ```bash
   git push origin v4.1.1
   ```

   Output: Tag synced to remote.

4. Update release notes surface

   - Read `RELEASES.md`
   - Ensure `Unreleased` section exists (for future work)
   - Create a new section for the current version
   - Output: `RELEASES.md` updated with version header

5. Generate GitHub release notes

   ```bash
   git log $(git describe --tags --abbrev=0 HEAD~1 2>/dev/null || git rev-list --max-parents=0 HEAD)..HEAD --oneline
   ```

   - Parse git log for feature/fix/docs changes
   - Read `RELEASES.md` section for current version
   - Structure release notes with: **What's New**, **Changed**, **Fixed**, **Infrastructure**, **Downstream Impact**
   - Save to `/tmp/release-notes.md`

   Output: Markdown release notes file

6. Create GitHub Release (MANDATORY)

   ```bash
   gh release create v4.1.1 --title "v4.1.1" --notes-file /tmp/release-notes.md
   ```

   Output: GitHub Release API object created.

**Error handling:**
- If tag already exists: Ask how to proceed (skip, overwrite with `-f`, use different tag)
- If no changes to commit: Skip steps 2–5, proceed directly to tagging
- If step 11 fails: Escalate to user (release creation is not optional)

**Latency enforcement:** Pre-push check runs `npm run check` (< 30s). Tag creation and GitHub Release use GitHub API (exempt from latency gate).

### Workflow 3: `/reconcile` (Workspace Entropy Audit)

**Canonical definition:** `.agent/workflows/reconcile.md`

**Execution phases:**

**Phase 1: Read & Inventory (Mechanical)**
1. List all files in active surfaces: `framework/`, `.agent/workflows/`, `scripts/`, root harness docs
2. Read canonical source documents: `AGENTS.md`, `framework/HE Index.md`, `framework/HE Skill Creation Standard.md`
3. Cross-check `README.md` against actual file structure
   Output: File inventory + canonical definitions loaded

**Phase 2: Analyse & Identify Issues (Agentic)**
4. Scan for: broken content, inconsistent terminology, duplication, missing cross-references, orphan concepts, structural issues, concept chain gaps
5. Examples:

- **Terminology mismatch:** Feature labeled `P0-9` should have header matching `framework/HE Index.md` classification (Foundation vs Pillar)
- **Duplication:** Same rule defined in multiple files with different wording
- **Orphan concepts:** Concept mentioned in support material but never linked to framework

   Output: Categorized issue list (Broken/Inconsistent/Duplicated/Missing/Orphan/Structural/Chain)

**Phase 3: Produce Reconciliation Report (Agentic)**
6. Create Markdown findings document: `.harness/reconciliation-findings.md`
7. Structure: Issue → Category → Impact → Proposed Fix → Effort (Light/Medium/Heavy)
8. Prioritize by effort; include effort estimates
   Output: Markdown findings report for user review

**Phase 4: Execute Approved Fixes (Mechanical)**
9. Apply Light fixes first (typos, numbering, terminology standardization)
10. Apply Medium fixes (cross-references, orphan integration)
11. Apply Heavy fixes (consolidation, deduplication) only if approved
12. Update `README.md` to reflect structural changes
13. Do NOT edit `docs/` unless user explicitly requests it
    Output: File changes applied

**Phase 5: Sync & Commit (Mechanical)**
14. Re-read changed files to verify no new issues introduced
15. Run `/ccp` workflow to commit with message: `docs: reconcile workspace entropy after [audit reason]`
    Output: Git commit with reconciliation changes

**Latency enforcement:** `npm run audit` (< 60s) validates post-reconciliation state. Must exit 0 before accepting merge.

### Output Format Standards

All command output must be machine-readable for agent consumption and human-readable for user review.

**Smoke (`npm run smoke`)**
- Exit code only: 0 (pass) or non-zero (fail)
- No JSON output required
- Pre-commit gate rejects on non-zero

**Check (`npm run check`)**
- Exit code: 0 (pass) or non-zero (fail)
- Summary format (JSON, optional): `{ "status": "pass" | "fail", "checks_run": N, "failures": [...] }`
- Human-readable output (Markdown): List of linting/spell/he-lint failures with remediation steps
- Pre-push gate enforces exit 0

**Audit (`npm run audit`)**
- Exit code: 0 (pass) or non-zero (fail)
- Structured output: `.harness/observation-report.json` (machine-readable)
- Human-readable output: `.harness/dashboard.md` (Markdown)
- JSON schema: `.harness/observation-report.schema.json`
- Pre-release gate requires exit 0

**LLM Review (`/reconcile`, `/polish`, etc.)**
- Output: Markdown findings + git commits
- Machine-readable state: `.harness/task-state.json` (for Ralph Loops tracking)
- No JSON requirement, but machine-parseable structure (lists, headers, code blocks)

## L4: Prevention

**`P0-9-1` Prevent Manual CLI Execution Without Wrappers:**

You must prevent agents from executing raw, multi-step system commands (git commit, npm run, git push, git tag, gh release) without standardization. Prevention rule:

- **Binding:** `.harness/prevention-rules-registry.json` entry `P0-9-manual-cli-execution` with enforcement reference to `npm run smoke` (pre-commit) and `he-lint.js` warning output
- **Mechanism:** `he-lint.js` must scan git logs (last 10 commits on current branch) for commit messages that indicate raw CLI usage without wrapper context (e.g., commit message says "run npm install" or "git reset" without mentioning `/ccp` or `/ccpr`)
- **Enforcement:** If detection occurs, `npm run smoke` issues a warning and suggests using the appropriate wrapper workflow
- **Declared Status:** DECLARED_UNMOUNTED (manual git log scanning is complex; recommend documenting best practices in AGENTS.md instead)
- **Alternative:** Document in AGENTS.md (already present per `## Workflows` section) that agents must use `/ccp`, `/ccpr`, `/reconcile` for standard operations

**`P0-9-2` Enforce Cost Tier Latency Targets:**

- **Binding:** `npm run smoke` must complete < 2s on clean harness state
- **Binding:** `npm run check` must complete < 30s on typical repository
- **Binding:** `npm run audit` must complete < 60s on typical repository
- **Enforcement:** CI gates reject runs exceeding thresholds; pre-commit hooks enforce smoke tier locally
- **Measurement:** Track command latency in `.harness/agent-logs.jsonl` with `duration_ms` field per AGENTS.md Tier 2 logging spec

## L5: Gap Signals

- Agents consistently fail on complex CLI flag syntax
- Command output is too long for the context window
- No standard "safe" version of destructive commands
- Intent of agent actions is obscured by raw command noise
- High variation in commit message quality and release note detail
- Coordination overhead from agents mis-ordering system commands
