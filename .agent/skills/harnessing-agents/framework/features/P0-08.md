# P0-8. Harness Versioning

> **Chain:** [EP-8](../principles/EP-08.md) → You cannot improve what you do not measure

## L2: Targeted Enhancement

Harness configurations are reproducible and comparable with data.

## L3: Design Decisions

VCS-tracked Config-as-code for agent prompts and tool definitions; semver for harness releases; immutable snapshotting of environment state; Machine-Readability First.

## L4: Concrete Actions & Tools

- **Action:** Build A/B testing pipeline to statistically compare harness variants.
- **Tool:** Version control (Git) for harness configs.
- **Tool:** Performance comparison dashboards.

## L4: Prevention

- **`P0-8` Prevent Unversioned Prompts:** You must prevent agents from using "latest" or unversioned prompt templates in production. Every prompt must be anchored to a specific Git hash or version tag.
- **`P0-8` Prevent Narrative Version Manifests:** All harness version manifests and state snapshots must be JSON-standardized to enable deterministic environment replication.

## Enforcement Bindings

- **Registry:** `.harness/prevention-rules-registry.json`
- **Schema:** `framework/schemas/prevention-rules-registry.schema.json`
- **Rule:** `P0-8-unversioned-prompts` → status `declared-unmounted`; no prompt-version scanner is mounted yet.
- **Rule:** `P0-8-version-manifests` → status `declared-unmounted`; no dedicated harness version-manifest artifact is mounted yet.

## L5: Gap Signals

- No way to compare different harness configurations
- Unable to reproduce a specific agent's failure due to environment drift
- Prompt changes deployed without version tags
- Multiple agents running different, incompatible harness versions
- No data on which configurations produce better agent output

- A/B comparison data available per config change
