# P2-5. Upstream Intake Gate

> **Chain:** [EP-14](../principles/EP-14.md) → Clarity before commitment

## L2: Targeted Enhancement

No planning or execution proceeds on unrecorded requirements.

## L3: Design Decisions

Intake validation checkpoint before planning; ledger entry verification (P1-10); Socratic qualification (P1-11); gated workflow prevention.

## L4: Concrete Actions & Tools

- **Action:** Implement a mandatory validation checkpoint that triggers before any planning or execution workflow.
- **Action:** The gate verifies that the incoming requirement has a corresponding entry in the Requirements Ledger (P1-10) before allowing execution to proceed.
- **Action:** Integrate with Socratic Questioning (P1-11) — the gate invokes the Socratic round if the requirement lacks sufficient clarity.
- **Tool:** Workflow guard scripts that check ledger state before proceeding.
- **Tool:** Automated intake forms that capture required fields (narrative, acceptance criteria, scope).

## L4: Prevention

- **`P2-5, P1-10` Prevent Unregistered Work:** You must prevent agents from starting planning or execution on requirements that have not been formally captured in the Requirements Ledger. Standardized entry sequence for all new work; automated risk assessment; triage loops; machine-readable intake records; Machine-Readability First.

## Enforcement Bindings

- **Registry:** `.harness/prevention-rules-registry.json`
- **Schema:** `framework/schemas/prevention-rules-registry.schema.json`
- **Rule:** `P2-5-unregistered-work` → status `implemented`; `scripts/he-lint.js` enforces `validatePlanRequirementIds()` and `validateRequirementsLedger()` against `PLANS.md` and `REQUIREMENTS.md`.

## L5: Gap Signals

- Agents start coding from ad-hoc chat requests with no recorded intake decision
- No record of why a task was prioritized or triaged
- High-risk operations are started without a tiered risk assessment
- Intake requests vary significantly in quality and detail
- No audit trail of upstream sources for project work
- No enforcement mechanism exists to prevent execution on unregistered requirements
- The Requirements Ledger exists but agents bypass it because no gate enforces usage
- Rework caused by misunderstood requirements that were never formally captured
