# P0-2. Filesystem, Git & File Locking

> **Chain:** [EP-2](../principles/EP-02.md) → State must outlive the session
>
> **Measurement Standards:** See [HE Measurement Standards.md](../HE%20Measurement%20Standards.md) for canonical L5 measurement methodology.
>
> **Registry:** All feature measurements are bound to `.harness/measurement-definitions.json` for operationalization and tracking.

## L2: Targeted Enhancement

Agent work is persistent, versioned, and conflict-free.

## L3: Design Decisions

Git-tracked workspaces per agent; per-agent branching strategy (worktrees or feature branches); file locking and task-claiming for MAS; rollback automation on test failure; Machine-Readability First.

> **P0-2 ↔ P0-1 Reconciliation:** Persistence (P0-2) applies to work products committed to Git, not to the execution environment. Sandboxes (P0-1) are ephemeral and reset after each session; Git ensures all valuable output survives the reset.

## Scope: SAS vs MAS

**SAS Status:** Complete

- Git-tracked workspaces per agent (live via git)
- Per-agent branching via worktrees (live via `git worktree`)
- Per-agent isolation prevents concurrent file conflicts
- Rollback via git reset and git revert (live)

**MAS Status:** Planned

- Distributed file locking for shared workspaces (deferred to MAS Phase 2)
- Consensus-based task claiming across agent pool (deferred to MAS Phase 2)
- Lock lease timeouts and deadlock detection (future infrastructure)

**Migration Path:** SAS implementations use `.git/` branching as their conflict-free isolation layer. MAS adds distributed file-locking (e.g., Redis, etcd, or filesystem locks) to scale beyond per-agent worktrees. No SAS refactor required if Git usage follows branch-per-task discipline documented in P1-9.

## L4: Concrete Actions & Tools

- **Action:** Provide a durable, versioned foundation for all agent and orchestrator outputs.
  - **Tool:** Git for version control and branching (SAS live).
  - **Tool:** Git Worktrees for concurrent agent isolation (SAS live via `git worktree add`).
  - **Acceptance Criteria:** All work products committed to Git; zero uncommitted changes at task completion.
  
- **Action:** Isolate agent work per branch to prevent concurrent overwrites.
  - **Tool:** Feature branch strategy or worktrees per agent (SAS live).
  - **Tool:** Pre-commit hooks validate branch naming per P1-9.
  - **Acceptance Criteria:** Each agent has exclusive write access to its own branch; merge conflicts resolved deterministically.

- **Action:** Implement file locking for MAS shared workspaces (deferred).
  - **Tool:** File locking mechanisms (e.g., `lockfile`, `flock`, Redis, etcd) for MAS shared workspaces (MAS future).
  - **Acceptance Criteria (future):** No concurrent writes to same file; lock lease timeouts prevent deadlocks.

- **Action:** Automate rollback on test failure (SAS via Git, MAS deferred).
  - **Tool:** `git revert` on failed pre-commit verification.
  - **Tool:** Transaction semantics for multi-agent writes (future MAS).
  - **Acceptance Criteria:** Failed commits do not persist; rollback logs recorded to `.harness/rollback-audit.jsonl`.

## L4: Prevention

- **`P0-2` Prevent State and File Conflicts:** You must prevent race conditions where multiple agents overwrite each other's code or claim the same tasks simultaneously. Prevent this by implementing explicit file locking, shared task lists, and breaking work down so teammates own different sets of files.
  - **SAS Enforcement:** Per-agent worktrees and branch isolation (live via git).
  - **MAS Enforcement (future):** Distributed file-locking and task-claiming mechanisms (deferred to MAS Phase 2).
  - **Registry Status:** `declared-unmounted` for MAS; SAS isolation via Git satisfies the constraint.

- **`P0-2` Prevent Narrative Structural Metadata:** All improvement policies and assessment data must be stored in machine-readable formats (JSON/YAML) to ensure automated alignment tracking.
  - **Enforcement Surface:** All feature definitions use JSON/YAML structures; no narrative-only metadata permitted.
  - **Registry Status:** `implemented` — schemas and linting enforce machine-readable format.
